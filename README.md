# dsh-vim

用键盘完成整个操作流程的插件，适用于 DeepSeek Harness Web / Desktop 客户端。

滚动、切会话、进输入框、退出输入框、改推理等级、换模型、重命名、归档、决定 Enter 发不发——每一步都有键。整个流程不用把手放回鼠标。

## 一条规则支撑全部

插件只做一件事：**保证每一颗键在任何时刻都是活的。**

宿主会在四个时刻把光标塞进输入框：首次打开页面、切换对话、**发完一条消息**、一轮任务跑完。每次落地，`d` / `e` / `f` 都变成死键，必须先按 Esc 才能滚。

本插件挡住了这四次。规则很简单：**输入框只在你要的时候才拿焦点。**

- 你点了输入框、按了 `Tab`、或者按了 `空格`——你**要**它，插件不插手。
- 宿主自己塞进去焦点——插件**立刻还给页面**，`d` / `e` / `f` 当场可用。

这不是"切换后 600ms 内的守卫"，是常驻规则。不管宿主的焦点来得多晚，只要不是你主动要的，就进不去。

挡住的只有富文本编辑器（这个宿主里就是消息输入框）。设置页、侧边栏搜索这些面板自己聚焦自己的字段，是面板的事，插件不碰。

这条规则是其余功能的前提。没有它，`d` / `e` / `f` 在最常见的三种情况下都是死的。

## 键位与功能绑定

这是本插件唯一的核心对照表。所有键都能在设置页改。

### 页面上的键（任务窗关闭时）

| 键 | 绑定功能 | 配置项 |
|---|---|---|
| `d` | **鼠标指着的那个窗格**向下滚动 | `downKey` |
| `e` | **鼠标指着的那个窗格**向上滚动 | `upKey` |
| `空格` | 进入输入框。**空着时再按一次 = 离开** | `focusKey` |
| `q` | 推理等级换下一档，循环。**只动等级，不动模型** | `effortKey` |
| `w` | 弹出模型选择窗；**窗内 = 确定切换** | `modelKey` |
| `Enter` | **在输入框里**：发送 / 换行 / 什么都不做 / 连按两下发送，四选一 | `sendMode` |
| `Ctrl/⌘+Enter` | 发送（**宿主自己的键**，任何档位下都有效） | — |

### 任务窗里的键（窗口打开时）

| 键 | 绑定功能 | 配置项 |
|---|---|---|
| `f` | 打开任务窗 / **窗内 = 前往选中的对话** | `paletteKey` |
| `e` | 上移选中项 | `paletteUpKey` |
| `d` | 下移选中项。走到末尾自动展开更早的 | `paletteDownKey` |
| `r` | 重命名选中的对话 | `paletteRenameKey` |
| `s` | 切换选中对话的**阶段**（讨论 / 编码 / 检查） | `paletteStageKey` |
| `g` | **归档**选中的对话 | `paletteArchiveKey` |
| `o` | 前往选中的对话 | `paletteEnterKey` |

### 模型窗里的键（窗口打开时）

模型窗复用任务窗的上下翻键，所以 `d` / `e` 在窗里是同一件事：

| 键 | 绑定功能 | 配置项 |
|---|---|---|
| `w` | **确定**，切到选中的模型（和它标着的档位）并关窗 | `modelKey` |
| `e` | 上移选中项 | `paletteUpKey` |
| `d` | 下移选中项。走到末尾回绕到第一个 | `paletteDownKey` |
| `Tab` | **换档位**：下一档，到头回绕；`Shift+Tab` 是上一档 | `modelLevelKey` |

不可改的键：

| 键 | 说明 |
|---|---|
| `Enter` | 窗内确认的常驻别名。改掉切换键之后仍然可用，也不许被别的座位占用 |
| `↑` / `↓` | 窗内移动选中项 |
| `←` / `→` | 窗内换档位，和 `Tab` / `Shift+Tab` 同一个动作 |
| `Esc` | 窗内唯一的取消键。**唯一保证能关掉窗口的键** |
| `Esc` | 输入框里：焦点交还页面。行为可关 |

**`Tab` 在模型窗里是档位键，不再移动选中行**（0.17 起）。移动选中行用 `d` / `e` 或 `↑` / `↓`。把 `modelLevelKey` 改到别的键，`Tab` 就退回它原来的「下移选中项」——不会变成一个什么都不做的键。

### `d` / `e` 的三个意思

`d` 和 `e` 在两组里都出现，这是故意的：

- 任务窗和模型窗**都关着**时：`d` / `e` = 滚动页面
- 任务窗**打开**时：`d` / `e` = 移动选中行
- 模型窗**打开**时：`d` / `e` = 移动选中项（和任务窗同一组键）；`Tab` = 换档位

窗口开着时键盘归窗，鼠标停在哪里都一样。所以 `f` → `d` `d` → `f` 这一套不会因为手边鼠标的位置而变意思。

两个窗不会同时认领键盘：模型窗开着时按 `f`，`f` 被模型窗吞掉，不会在它后面再开一个任务窗。想先挑模型再挑对话，就 `Esc` 掉一个再开另一个。

同一组内不许重复，跨组随便撞。

### 焦点在输入框里时

插件**完全不介入**。`d` / `e` / `f` / `q` / `w` 都是普通字符，用来打字。

唯一的例外是聚焦键（默认 `空格`）：**输入框里一个字都没有时，它把焦点还回来**。有内容时它还是普通的空格。焦点停在按钮上时空格仍然是"按下这个按钮"，插件不抢。

### 发完一条消息之后

按 Enter 发送的那一刻，插件会把焦点交还页面，`d` / `e` / `f` 当场可用——**按 `f` 打开任务窗时，它不会变成往草稿里打的第二个字**。想接着写下一条，按一下聚焦键（默认 `空格`）就行，**草稿一个字都不会少**：这里只挪焦点，从不碰文本。

为什么需要这一条：输入框在发送前后始终保持着 DOM 焦点，宿主再调一次 `focus()` 是个空操作，**根本不会触发 `focusin`**。所以「拦住宿主塞进来的焦点」那条常驻规则在这里无从下手——插件只能自己发一次 `blur()`。

判定为"一次发送"的条件（缺一不动）：焦点在消息框里 · 不在中文输入法组字中 · 候选列表（`/` 菜单、`@` 菜单）没开 · 输入框非空 · 按的是裸 `Enter`（`Enter` 设置为"换行"或"什么都不做"时不算，那两种模式下只有 `Ctrl` / `⌘` + `Enter` 才发送；设置为"连按两下 Enter 发送"时，第二下 `Enter` 算）。

探测排在 `0ms` 和 `120ms` 两处，避开宿主自己处理发送的那一拍；这两处都不碰文本，猜错的代价只是"你得再按一次空格"。期间只要你自己要了键盘（点一下、`Tab`、聚焦键、开始打字），交还立刻作废。

**点发送按钮这条路本来就没这个问题**：按下按钮时 `pointerdown` 已经作废了那张"用户要键盘"的通行证，宿主随后塞进来的焦点会被老规则直接弹回去。

### 四个焦点开关

在设置页里，不占键位，四项默认都开：

| 开关 | 作用 |
|---|---|
| 不自动聚焦输入框 | 宿主塞进来的焦点立刻还给页面 |
| 发完消息交还键盘 | 消息发出去的那一刻，焦点还给页面 |
| 空格离开空输入框 | 空输入框里再按一次空格 = 离开 |
| Esc 离开输入框 | 输入框里按 Esc = 离开 |

## 键盘流程

### 滚动

按 `d` / `e` 时，插件先问一件事：**你现在鼠标指着的是哪一块？** 然后滚那一块。

| 鼠标停在 | `d` / `e` 滚的是 |
|---|---|
| 对话正文 | 对话内容 |
| 侧边栏 | 会话列表、文件树，以及侧边栏里任何可滚的部分 |
| 右侧栏 / 插件面板 | 那一块自己的内容 |

具体判法：从鼠标位置取一个元素，沿着它往上找，找到第一个「能滚」的元素就算数。判「能滚」的条件是：CSS 的 `overflow` 是 `auto` / `scroll` / `overlay`，并且内容确实比容器高。

所以它不认「这是侧边栏」「这是正文」这种标签。**它只认「这块现在能滚」**。这也是侧边栏不需要专门代码的原因。

判定顺序：

1. **鼠标指着的窗格**——绝大多数时候走的路。
2. **焦点所在的窗格**——鼠标还没动过（纯键盘操作），或者鼠标停在滚不动的地方（窗格标题、两栏之间的缝）。此时回退到正文。
3. **窗口正中间**——正文。
4. **页面上最大的可滚容器**——最后的兜底。

细节：

- 鼠标位置只在**按下 `d` / `e` 的那一刻**读一次。单独移动鼠标不会滚动任何东西。
- 按住不放时把鼠标移到另一块，剩下的连发跟着换过去。
- **并列的块不接力**：侧边栏滚到底不会跑去滚正文。但**嵌套的块会向上接力**，和滚轮一样——内层列表到了头，外层面板接着滚。
- 窗口失焦后不再使用记下的鼠标位置。浏览器在别的窗口处于前台时不派发鼠标移动事件，那个位置可能是旧的。
- 插件里**没有任何写死的选择器**。

### 输入框：空格进，空格出

聚焦键不只是"进去"。**输入框里一个字都没打的时候，再按一次就出来**——焦点还给页面，`d` / `e` / `f` 立刻可用。进出同一个键。

判据只有一条：**编辑器的文字是不是空的**。这正是宿主自己判断"要不要显示占位提示"用的那条（`draft === ""`）。

- **空**：按下去 = 离开。空编辑器读出来就是空白（Lexical 的空段落是一个换行符），所以这里不看 DOM。
- **有内容**：还是普通的空格，该打字打字。`@` 提到的文件在草稿里是一个引用字符，同样算内容。
- **只有附件、没有文字**时算空。附件不在编辑器的文字里。
- 按住不放不会来回切。第一次按下离开，后面的连发什么都不做。

为什么需要它：**Esc 不总是能用**（见下节）。这时候空格就是唯一的出路。

### Esc 和输入框

宿主自己的 Esc 逻辑是：关掉候选气泡 → 问一句"这次转写要不要中断" → 被消费就到此为止，**它从不把焦点还回来**。所以常见情况下这个键是空放的，插件接管了它。

- 在输入框里按 Esc → 焦点交还页面，`d` / `e` 立刻恢复。
- **不让宿主的 Esc 失效**。插件在**冒泡阶段**才动手，等宿主先处理。宿主已经处理过就让路。
- **正在跑的任务，Esc 完全归宿主**。宿主用 Esc 中断当前转写，而且中断时不标记事件已被处理，所以让路机制看不见它。这种情况下插件**什么都不做**——一次按键毁掉一个你根本没打算停的任务，是最坏的一种意外。
  - 只看**当前屏幕上那条**在不在跑。后台别的对话在跑，不影响。
  - 宿主没发布状态源时，退回目录里的 `running` 布尔值，照样保护。

四条焦点规则互相独立：**空格**是你让输入框进来（空的时候也是你让它出去），**Esc** 是你自己出去，**不自动聚焦**是插件不让宿主硬塞，**发完交还**是消息一出去就把键盘还回来。

### 任务窗

按 `f` 弹出一个浮层，列出可以切回去的对话。**选好之后再按一次 `f` 就过去了**——开窗、选人、跳过去，同一个键按两下。

第一行**永远是你此刻所在的那条对话**（右侧挂一个紫色的 `当前` 标签），其余按最近使用排。第一行回答的是"我在哪"，不是"谁最近动过"。

每行有七格：文件夹、对话名、`当前` 标签、**阶段**、状态（含计时）、轮数、时间。

`当前` 是独立的一格，排在状态**前面**——它说的是"这条是哪一条"，不是"它现在在干什么"，所以不占对话名的地方，也不会被长名字挤掉；反过来，对话名也不再被一个前缀吃掉，所有行的名字都从同一个位置开始。那条对话不在列表里时（比如它被归档了），**这一格整列收起来**，不给其余行留一条空边。

这七格的宽度**按当前这一屏里最宽的那一格算，每个都贴着自己那一列的右边**。不这么做的话，每行会各按各的内容排，`13 轮` 和 `刚刚完成` 就会一行的位置一个样。计时变长（`59 秒` → `1 分 0 秒`）时会重新量一次那一列，所以数字长大不会挤到名字。

**阶段**说的是**这一轮在讨论、编码还是检查**——回答"这件事现在做到哪了"，而下面那个状态回答"它现在跑没跑"。两者不是一回事：一条对话可以正跑着编码，也可以跑完了等你验收、状态显示`刚刚完成`而阶段停在`检查`。

这一格**把三个词都摆出来**，当前那个高亮：

```
讨论  编码  检查        ← 未标注：三个都是灰的
讨论 [编码] 检查        ← 标注后：当前那个亮起来（这里用方括号示意）
```

- **点一个词就标上**。不用先知道有哪些选项、也不用记顺序——每一行都把整份词表摆在你眼前。
- **点已经亮的那个 = 取消标记**。所以"怎么摘掉"不需要多余的说法，亮的那个就是回头路。
- **点词只改阶段，不会跳到那条对话**（行的其余部分才是切换）。
- **窗内按 `s`** 按同样顺序推进：讨论 → 编码 → 检查 → 未标注 → 讨论。键盘用户走这条路，看到的东西和点的一样。
- 标注**跟着对话走**：关掉任务窗在，刷新页面在（存在 `localStorage` 的 `dsh-vim/phases/v1`）。
- 这一版标注是**你自己点上去的**。阶段这个词表是插件自己的，不绑定任何宿主投影——将来要让它自己判断（读 goal、读 Agent 写的标记），只要往这个账本里写同一个词表，这一格和存储都不用动。

**状态标签**告诉你这条对话现在在干什么：

| 标签 | 含义 |
|---|---|
| 等待批准 / 等待计划审阅 / 等待回答 | 卡在需要你动手的地方 |
| 进行中 | 正在跑（模型或子代理） |
| 刚刚完成 | 跑完了，而且你还没去看 |
| （无标签） | 空闲 |

优先级和侧边栏一致：**等你 > 在跑 > 刚完成**。状态会实时更新，它跑完的那一刻标签就变了，不用重开弹窗。

**正在跑的带一个计时**，写在状态标签里面，比如 `进行中 · 3 分 20 秒`，开着窗的时候**每秒自己走**。等批准、等回答也算在飞的这一轮。它只改那一块标签的字，不重画列表，所以你正在选的行、正在改的名字都不会被打断。

计时是怎么来的：宿主**没有发布开始时间**（状态里只有 `running` 布尔值，会话摘要里一个时间戳都没有），所以插件自己盯着状态源，**从页面启动就盯着**，看到某条会话从"不在跑"变成"在跑"就记下那一刻。因此窗口什么时候开的都没关系，十分钟前开始的任务就显示十分钟。

**起点会落到 localStorage**（`dsh-vim/runs/v1`），所以刷新页面、重载插件、重启渲染进程都不会把计时打断。

拿不到起点的情况只有两种：这是这个浏览器**第一次**见到这条会话在跑（换了设备、清了存储、或者起点超过 12 小时），或者这一页已经开了一分多钟而那条会话才第一次出现。这两种都**不显示计时**，只留「进行中」。编一个起点出来不如不显示。

**轮数**（比如 `13 轮`）不在会话列表里，宿主只把 `title` 放进列表，所以要单独去问：

- **弹窗不会等它**。窗口瞬间就开，轮数后到，来了自己填上去。
- 一次最多同时问 3 个，单个最多等 1.5 秒，超时就不显示。
- 按 `会话 + updatedAt` 缓存，对话没动过就不会重复问。
- 读不到、宿主没这个投影、或者抛异常——一律不显示，也不重试。

列表**不贪心**：

- **已归档的不展示**。
- **空的占位会话不展示**——那是"新对话"的临时槽，切过去是空的。
- **打开时只给最近 12 小时的**，最多 20 条。**当前对话不受这个限制**：它永远在第一行。
- **更早的在按 `d` 往下走的时候才展开**，每次多 20 条。
- 最近 12 小时一条都没有时，退回显示最新的一批，不开空窗。

**重命名**：窗内按 `r`，选中那行的标题变成一个输入框，原标题整段选中。`Enter` 确认，`Esc` 放弃。

- 提交前去掉首尾空格。只有空格的名字会被拒绝，框留着让你改。
- 名字没变就直接收起输入框，不白跑一趟宿主。
- 失败会说话：宿主的拒绝理由显示在底栏，输入框不关，名字不丢。
- 重命名不导航。确认后窗口还开着，想过去就再按 `f`。
- **编辑期间键盘完全归输入框**：`d` / `e` / `f` 都只是普通字符，不会翻列表、不会跳走、也不会关窗。

**归档**：窗内按 `g`，把选中的那条对话收起来。走的是**宿主自己的归档动作**（`uiWorkspace.archiveSession`），和你在侧边栏里手动归档是同一件事。

- **正在跑任务的对话不会被归档**。宿主本身就会拒绝这种请求（错误码 `workspace/session-active`，并列出在跑的是哪个 turn / job）；插件**故意不带** `stopActivity` 这个参数——带了就等于让一个按键替你停掉任务，而**一次按键毁掉你根本没打算停的任务，是最坏的一种意外**，这条原则和 Esc 完全一致。遇到这种对话，底栏会说「这条对话正在跑任务，先停下来再归档」，把决定权还给你。
- **归档没有撤销键**，但宿主自己的「已归档」入口能找回来。插件不替宿主做回收站。
- **窗不关**，方便连着归档几条；被归档的那行由宿主从列表里拿掉（插件自己不动列表）。
- **归档的正是屏幕上这条时，主视图会跟着清空**——这是宿主的行为，和手动归档一样。
- **失败会说话**：宿主的拒绝理由显示在底栏，那行留在原地，可以再试。
- **宿主没发布归档动作时**，`g` 会在底栏写明"这个宿主不支持归档对话"，而不是默默什么都不做。

**任务窗不模态、也不会自己消失**。按 `f` 打开之后它一直在，只有 `Esc`、或者选中一条并切过去能让它消失。点背板、点正文、打字、失焦、切标签页都不关。

**唯一的例外是窗自己没有认领的滚动键**。把窗的上下翻键改到别的字母上（比如 `j` / `k`），`d` / `e` 就不再是窗的键，落回页面去滚正文，窗照旧留着。想边读边挑就这样配。

### 推理等级

按 `q` 把**当前对话**的推理等级换下一档，到头回绕。**模型不动**——它只改推理强度，和 composer 那个模型菜单里的「推理」行做的是同一件事，所以两边看到的是同一个选择。

- **档位跟着模型走**：顺序就是宿主自己那个菜单的顺序。模型声明了默认档时，是它公布的那几档；没声明时前面多一项「提供方默认」。适配器没公布等级时，`q` 告诉你一句，什么都不会发生。
- **每按一下都有回话**：输入框上方浮出一条 1.6 秒的提示，写着换到哪一档、第几档，比如 `推理等级 高  3/3`。失败理由也写在同一条上，不会按了没反应。
- 提示贴着输入框上沿，输入框自己挪了它也跟着挪。宿主万一没有富文本输入框，提示退回窗口顶部。
- **按住不算连按**：系统连发被吞掉，必须一下一下按。
- **正在跑的任务不受影响**：完整选择从下一轮请求开始生效。
- **输入框里它就是个普通字母**。**任务窗开着也能按**——它是页面的键，不是任务窗的键。

为什么用循环而不是弹窗：档位通常只有 3–5 个，开窗、选行、关窗比按两三下慢。

### 模型选择窗

按 `w` 弹出一个小窗，每一行是一个模型，**右边把它的全部推理档位都列出来**，高亮的那一档就是这一行会提交的档位。

**先在设置页勾一遍**：设置 → Vim 滚动 → **快捷键 → 常用模型**，清单从宿主自己的模型目录里读，勾哪几个、`↑` `↓` 怎么排，弹出的窗里就怎么列。

```
┌ 切换模型 ─────────────────────────────── 3 个 ┐
│     DeepSeek Chat       无档位      deepseek   │
│ 当前 DeepSeek Reasoner  低 [中] 高  deepseek   │
│     Space Bunny Free    无档位      bunny      │
├────────────────────────────────────────────────┤
│ w 确定 · d/e 选择 · Tab 档位 · Esc 取消         │
└────────────────────────────────────────────────┘
▸ = 键盘选中的行    [中] = 这一行会提交的档位
```

`当前` 标签在最前面，模型名、档位、提供方依次跟在后面——没被标的那几行把标签那一格空着，所以模型名始终对齐在同一列。

一次完整的操作：

1. `w` 开窗
2. `d` / `e` 上下选模型（`↑` `↓` 也行）
3. 想改档位就按 `Tab`（`Shift+Tab` 反向，`←` `→` 同义）；不改就跳过
4. `w` 确定，切过去并关窗

- **开窗时选中「当前」那一行**，所以进去第一眼就知道自己在哪。那一行最前面挂一个紫色的 `当前` 标签——这是循环做不到的：循环要按一下才知道自己走到哪，这个窗在你按任何键之前就说了。
- **每行的档位都列全、平铺在一行上，当前档高亮**。当前模型那一行高亮的就是当前档，一眼对上 composer 里显示的推理等级。
- **只选模型不碰档位时，档位跟着走**：新模型也公布当前那一档就带过去；否则不提交等级，由宿主落到那个模型自己的默认档。行上高亮的就是这个结果——**看到哪一档，切过去就是哪一档**。
- **按了 `Tab` 就是明确指定这一档**，确定时原样提交。
- **不动鼠标也能点**：点某一行 = 选中并确定；**点某个档位 = 切到这个模型 + 这个档位**，一步到位。
- **`Esc` 取消**。**取消不提交任何东西**：开窗只是读一遍目录，来回翻几下再 Esc，宿主那边什么都没发生。
- **窗开着时键盘归它**：`w`、`d`、`e`、`↑` `↓`、`Tab`、`←` `→`、`Enter`、`Esc` 都是窗的键，别的字母被吞掉，不会漏到页面上。**`q` 也被吞掉**——窗正在画档位，让它在背后偷偷改档位会让高亮对不上。
- **`Enter` 是确定的常驻别名**，和任务窗一样。
- **确认失败时窗不关**，宿主的拒绝理由写在窗底栏，选中的那行还在，可以直接改选或再试一次。成功才关窗，回一条 1.6 秒的提示，写着切到了哪个模型和哪一档（`模型 DeepSeek Reasoner · 高`）。
- **正在提交时窗是冻的**：切完之前再按 `w` 不会提交第二次。
- **当前模型不在清单里**（会话的默认模型、或一个你后来删掉的）时，选中落在第一行，而不是没有选中。
- **目录里已经不提供的模型不会出现在窗里**。所以一个提供方登出了，窗里就少几行，清单本身不会被改掉。
- **没公布档位的模型显示灰字「无档位」**，按 `Tab` 会在窗底栏说明一句，什么都不会发生。
- **换行会丢掉手动改过的档位**：档位标记只属于你正停在的那一行，移到别的行再移回来，它回到「跟着走」的规则。一次选择、一次确定，不做逐行记忆。
- 其余和 `q` 一样：**输入框里它是普通字母**、**任务窗开着也能按**（会在任务窗上面开）、**正在跑的任务不受影响**、**按住不算连按**。

**清单为空**、或**清单里的模型当前都不可用**时，`w` 只提示一句，**不开一个空窗**——一个没有可选项的窗除了让你按 Esc 之外没有别的用处。

**要知道的一件事**：换模型会在**下一条请求**之前，往对话里插一条宿主自己的提示——`[model changed: …]`，告诉你上面几轮是哪个模型写的。这是宿主行为，插件改不了；切换还会减少提供方侧的缓存复用。

### Enter 做什么

设置页有一项 **「Enter 做什么」**，四档：

| 档位 | 裸 Enter | 换行 | 发送 |
|---|---|---|---|
| **发送**（默认） | 发送 | `Shift+Enter` | `Enter` · `Ctrl/⌘+Enter` |
| **换行** | 插入换行 | `Enter` · `Shift+Enter` | `Ctrl/⌘+Enter` |
| **什么都不做** | 什么都不做 | `Shift+Enter` | `Ctrl/⌘+Enter` |
| **连按两下 Enter 发送** | 插入换行 | `Enter` · `Shift+Enter` | **连按两下 `Enter`**（250ms 内） · `Ctrl/⌘+Enter` |

**默认不改宿主行为**：让每个对话换一种发送方式，不该由一个滚动插件在装上时替你决定。要改自己去设置页切一下，即时生效。

- **`Ctrl/⌘+Enter` 是宿主自己的发送快捷键，不是插件加的**——所以后三档没有另造一个发送键。Mac 上提示写 `Cmd`、其他平台写 `Ctrl`。
- **「连按两下 Enter 发送」是为记不住快捷键的人准备的**：它和任务窗的 `f` 两下、模型窗的 `w` 两下是同一种手势——同一个键按两下就是确认。第一下 Enter **照常立刻换行，不延迟**；250ms 内再按一下才发送。中间打了别的字、或者间隔超过 250ms，就当成两个段落，第二下仍然是换行。**想连打两下空一行的话，改用 `Shift+Enter`**——它在任何档位下都只换行、不发送。
- **选「换行」/「什么都不做」/「连按两下 Enter 发送」时，输入框下方那一行常驻一句淡灰提示**，写明现在按什么发送，比如 `Enter 换行 · 连按两下 Enter 发送 · Ctrl+Enter 发送`。它挂在宿主给输入框预留的那一行里（`conversation.composer.dock`，上下文用量表旁边），水平居中，跟输入框一起长高；切回「发送」立刻消失。
  - 这一行是**通过宿主自己的 slot 注册进去的 React 组件**，不是插件往页面上贴的元素。所以位置、居中、跟随布局全部由宿主负责，插件不用量、也不用跟着草稿高度重算。
  - 提示**不画背景、不画边框**，借宿主自己的弱化文字颜色，明暗主题下都读得清；`pointer-events: none`，不挡点击、不吃按键。
  - 只在**消息输入框里**生效。终端、任务窗的重命名框、计划编辑器、设置页的字段——Enter 一律照旧。
- **斜杠菜单、`@` 引用这类候选列表开着时，Enter 永远归它**：那是"选中高亮项"，插件不插手。所以打 `/plan` 再按 Enter 仍然是执行命令，而不是换行。
- **输入法合成中的 Enter 不碰**：候选词上屏那一下照常走输入法。
- **实现上不插字符**：拦截掉的那一下，是把宿主自己的 `Shift+Enter` 换行手势（`client.js` 的 `breakLine`）递回输入框。所以换行拿到的是和手按 `Shift+Enter` 完全一样的软换行，不是新段落。
- **双 Enter 档的发送走的是宿主自己的键**：第二下不是插件自己去点发送按钮，而是把宿主自己的 `Ctrl/⌘+Enter`（`client.js` 的 `sendFromComposer`）递给输入框。走的是宿主真实的发送路径，草稿一个字都不动。**这个改写出来的键会被打上标记**（`REWRITTEN_FLAG`）——它会冒泡回插件自己的监听器，不打标记的话插件会把它当成"用户又按了一次键"，配对当场失效（0.15.1 修的就是这个）。
- **按住 Enter 不会发送**：只有"抬起再按下"才算第二下，键盘自动连发不算。这是双 Enter 档最重要的一条安全线。
- **四档都只管这个插件管的输入框**：其他窗口、其他应用、其他输入框不受影响。

### 手感

滚动不是"按一次瞬移一段"，而是 rAF 驱动的缓动：每次按键把目标位置推进 `step` 像素，实际位置按 `1 - exp(-dt/tau)` 逐帧逼近，因此帧率无关、且不会越过目标。

按住时**不依赖操作系统的键盘重复**（那个有 ~500ms 首延迟且节奏不匀），改为自己接管连发并逐步加速（65 ms → 45 ms）。

## 设置页面

设置 → **Vim 滚动**。改动**即时生效**，不需要重启。

**快捷键**：见上面的「键位与功能绑定」。

**常用模型**：从宿主自己的模型目录里勾，勾哪几个、什么顺序，`w` 弹出的窗里就怎么列。读不出来或宿主没发布目录时，这一组会写明为什么，而不是空着一片。

**模型窗：换档位**（`modelLevelKey`，默认 `Tab`）：模型窗里换推理档位的键，`Shift` + 它反向。只在模型窗里有效。

**焦点**：Esc 离开输入框；空格离开空输入框；不自动聚焦输入框；发完消息交还键盘；**Enter 做什么**（发送 / 换行 / 什么都不做 / 连按两下发送，见下）。

**弹窗外观**：字体大小 11–20 px；弹窗宽度 480–1400 px（再宽也会被 `94vw` 兜住）；弹窗高度 40–95 vh（用 vh 所以换屏幕跟着走）；行距 3–14 px；弹出位置顶部 / 居中 / 底部。

**速度与手感**：滚动步长 40–600 px；缓动时长 10–250 ms（越大越绵软，越小越跟手）；连发延迟 80–800 ms。

**焦点**：四个开关，见上。

**顶/底留白会自己让路**：把高度拉到 95vh 时，14vh 的上/下边距会缩到 3vh，保证整块还在屏幕里。让掉的是边距，不是你要的高度。

配置存在浏览器 localStorage 的 `dsh-vim/settings/v1` 下，跟着这台设备走，升级插件不会被清掉。

### 升级

从 0.1.x 到 0.9.x 升级**不需要改任何东西**，你原来的绑定原样保留。下面这些版本改了行为：

| 从 | 变成了什么 | 要做什么 |
|---|---|---|
| 0.1.x | `f` 的出厂默认从「向上滚动」变成「任务窗」。滚动和任务窗现在是两组键，`f` 同时是上滚和开关弹窗不冲突。唯一被覆盖的是上滚的**出厂默认**：从 `f` 变成 `e` | 不用动 |
| 0.4.x | 「聚焦输入框」的出厂键是**空格**。原来叫「切换后不聚焦输入框」的那项还是同一个开关（配置项名没变，你关掉过就还是关的），范围从"切换之后的一小段"扩成了"任何时候" | 不用动 |
| 0.5.x | 任务窗里按打开键**不再关窗，而是前往选中的对话**（`f` 连按两下 = 跳过去）。关窗用 `Esc` | 不习惯就把「任务窗」那个键改到别的字母上，它就只负责开窗 |
| 0.6.x | 窗内多了 `r` 重命名，行首多了文件夹标签 | 宿主没发布那个服务时分别退化成"不支持重命名"和"不显示文件夹" |
| 0.7.x | 输入框空着的时候，聚焦键（默认空格）再按一次 = **离开输入框** | 不想要就去设置里关掉「空格离开空输入框」 |
| 0.8.x | 任务窗变大两次（560 → 780 → 900px 宽，70 → 78 → 82vh 高）；正在跑的对话多了计时；状态 / 轮数 / 时间三列改成按全列表最宽的一格对齐到右边 | 计时需要插件常驻订阅状态源，多出来的开销就是一次 Map 遍历 |
| 0.9.x | 设置页多了**宽度 / 高度 / 行距**三个滑块（配置项 `paletteWidth` / `paletteHeight` / `paletteRow`） | 老配置读到就用默认值 |
| 0.10.x | 多了 `q`（推理等级）；计时起点落 localStorage；任务窗不再模态；列表第一行钉住当前对话 | 不想要常驻？按 `Esc` 任务窗就走 |
| 0.11.x | 任务窗多了**阶段**一列和 `s`（切换阶段）。阶段是手动标的，落在 `localStorage` 的 `dsh-vim/phases/v1` | 不用动。`s` 和 `r` 同属一组，改键时注意别撞 |
| 0.13.x | 多了 `w`（常用模型）和设置页里的**常用模型**清单（配置项 `modelKey` / `favorites`）。清单出厂是空的，`w` 会提示去设置 | 第一次用：设置 → Vim 滚动 → 快捷键 → 常用模型，勾几个。`w` 和 `q` / `d` / `e` / 空格同属一组 |
| 0.14.x | `w` 从「循环到下一个」改成**弹出模型选择窗**：`w` 开窗、`d` / `e` 选、`w` 确定、`Esc` 取消。清单、配置项和键位都不变，取消不再需要按回来 | 不用动。原来按 `n` 下换 `n` 个模型，现在直接选那一行 |
| 0.15.x | 「Enter 做什么」多了第四档 **「连按两下 Enter 发送」**（`sendMode: 'double'`）：第一下照常换行，250ms 内再按一下发送 | 不用动。默认仍是「发送」，前三档行为一字未改；只有你自己切过去才生效 |
| 0.15.1 | 修掉第四档**按两下不发送**的问题：插件改写后递回输入框的那个键会冒泡回插件自己的监听器，被误判成"中间夹了别的键"，配对当场失效 | 不用动。如果你之前试过第四档觉得没反应，现在再试一次 |
| 0.16.x | **`g` 从「前往选中的对话」改成「归档选中的对话」**；切换改到 `o`。新增配置项 `paletteArchiveKey`，归档走宿主自己的动作 | **自动迁移，不用动**：你的存储里如果 `paletteEnterKey` 还是旧的出厂 `g`，插件会把它挪到 `o` 并把 `g` 给归档；如果你自己把切换键改成了别的字母，那个字母原样保留，归档另找一个空闲键 |
| 0.17.x | **模型窗里同时列出每个模型的全部推理档位**，高亮当前档；新增配置项 `modelLevelKey`（默认 `Tab`）用来换档位，`Shift` 反向，`←` `→` 同义。点某个档位 = 切到这个模型 + 这个档位。切换成功的提示带上档位名 | **`Tab` 在模型窗里改成换档位**，移动选中行改用 `d` / `e` / `↑` / `↓`。把 `modelLevelKey` 改到别的键，`Tab` 会退回「下移选中项」，所以不习惯的话改一下就好。已有的键位、清单、其他行为都不变 |

## 安装

`desktop` profile 由 Electron 应用独占，CLI 会被拒绝。走应用内的插件管理器：

1. 侧边栏 → **插件** 页
2. **安装组合包**，spec 填本仓库的绝对路径
3. 若未立即生效，重启 DSH Desktop

其他 profile（如 `web`）可以直接用 CLI：

```sh
dsh plugin --profile web add "G:\桌面\dsh-vim"
```

本包没有任何依赖、没有 install/build 脚本，因此**不需要** pnpm 的 `allowBuilds` 授权。

## 实现

插件**没有 DOM 抓取**，用的是宿主已有的客户端服务：

| 用途 | 服务 |
|---|---|
| 会话列表 | `ctx.sessions.list.getSnapshot()` |
| 状态 | `ctx.get('uiSession').sessionStatus` |
| 轮数 | `ctx.sessions.retainScope(id, 'dsh-vim')` → `projections.faceOf('sessionStats')` |
| 文件夹 / 归档 | `ctx.workspaces.list.getSnapshot()` 的 `items[].sessionIds` 和 `archivedSessionIds` |
| 切换 | `ctx.get('uiWorkspace').openSession(id)` |
| 重命名 | `ctx.sessions.using(id, { source: 'dsh-vim' }, ref => ref.binding.session.rename(title))` |
| 归档 | `ctx.uiWorkspace.archiveSession(id, {})` — **不带** `stopActivity`，见上文「归档」 |
| 推理等级 | `directory.store.getSnapshot()` / `directory.select({...})` |
| 常用模型（弹窗列表 / 切换） | `directory.load()` 的 `groups` → `directory.select({provider, model, reasoningEffort})` |
| 常用模型（设置页列表） | `ctx.modelDirectories.catalog.load()`，不需要打开任何会话 |

过滤规则和状态优先级都照宿主自己的 `sessionVisible` / `sessionStatuses` 抄的，所以任务窗里能看到的、标出来的，就是侧边栏里能看到的。

这些服务是**懒探测**的，没有写进 `inject`。缺哪个服务就只少对应的那部分，其余照常工作：

- 没有 `sessions` / `uiWorkspace` → 丢的只是任务窗，**滚动照常工作**，`f` 什么都不做也不吞键。
- 没有 `workspaces` → 任务窗照常工作，只是不做归档过滤、行上也没有文件夹。
- 没有 `uiSession` → 状态退化成目录里的 `running` 布尔值。
- 没有 `retainScope` → 没有轮数，别的什么都不少。
- 没有 `using` → `r` 会告诉你这个宿主不支持重命名。
- 没有 `uiWorkspace.archiveSession` → `g` 会告诉你这个宿主不支持归档。
- 没有 `modelDirectories` → `q` 和 `w` 各提示一句，滚动和任务窗都不受影响。

**一个必须避开的坑**：retain 的来源绝对不能用 `mainView`。`uiSession.reconcileStatus()` 里有 `if (isMain(id)) this.completionUnread.delete(id)`，一旦某个会话被当作主视图挂起，它的「刚刚完成」标记就被清掉了。所以插件用的是 `'dsh-vim'` 这个私有来源。轮数和重命名两处都守这条，测试里有专门的用例。

## 调试

DevTools 控制台（`Ctrl+Shift+I`）：

```js
window.__dshVim.settings()                       // 读当前配置
window.__dshVim.update({ downKey: 'j' })         // 改配置，和设置页等价，会持久化
window.__dshVim.reset()                          // 恢复默认
window.__dshVim.palette()                        // 任务窗状态
window.__dshVim.palette(true)                    // 直接弹开任务窗（不等按键）
window.__dshVim.phase()                          // 全部阶段标注 { 会话 id: 阶段 }
window.__dshVim.phase('会话 id')                  // 读一条（未标注返回 ''）
window.__dshVim.phase('会话 id', 'code')          // 标成编码
window.__dshVim.phase('会话 id', null, true)      // 按一次循环推进
window.__dshVim.clearPhases()                     // 清掉全部标注
window.__dshVim.probe()                          // 当前会被滚动的元素 + 记下的鼠标位置 + 输入框状态
window.__dshVim.models()                         // 常用模型清单 + 目录提供了什么 + 按得到哪几个（Promise）
window.__dshVim.modelPick()                      // 模型窗状态：open / index / total / level / marked / levelSet / rows（每行带 levels 和 marked）
window.__dshVim.modelPick(true)                  // 直接弹开模型窗（不等按键）
window.__dshVim.debug(true)                      // 每次滚动打印一行日志
window.__dshVim.stop()                           // 立刻停住动画与连发，关掉两个窗
```

常见问题：

- **按键没反应** → `probe()` 返回 `element: null` 说明那个点上没有可滚容器。返回了侧边栏而不是正文，**那正是鼠标指着的地方**，把鼠标移回正文即可。`pointer.seen === false` 表示插件还没见过鼠标（纯键盘操作），此时走焦点/中间那条兜底路径。
- **设置页没出现但滚动正常** → 看控制台里有没有 `[dsh-vim] settings section registration failed`。滚动本身不受影响。
- **任务窗按了没反应** → `palette()` 看 `available` 是不是 `false`。是的话说明这个宿主没有发布 `sessions` / `uiWorkspace`。
- **归档的对话还在列表里** → 这个宿主没发布 `workspaces` 注册表，此时任务窗不做归档过滤。
- **按 `g` 说「先停下来再归档」** → 那条对话正在跑任务。宿主会拒绝归档有工作在跑的会话，而插件不会替你停它——停掉之后（或等它跑完）再按一次 `g`。
- **`w` 说「还没配置常用模型」** → 设置页那一组还没勾。去设置 → Vim 滚动 → 快捷键 → 常用模型。
- **`w` 什么都没弹** → `models()` 看 `entries` 是不是空的。空而 `favorites` 不空，说明清单里的模型当前都不在目录里（多半是提供方登出了），这种情况只提示一句，不开空窗。`modelPick()` 的 `open` 是 `false` 也说明窗没开起来。
- **模型窗里选了但没切过去** → `modelPick().notice` 里是宿主给的理由。

## 结构

```
dsh-vim/
├── package.json        dsh.bundle.patch + dsh.client
├── cordis.patch.yml    insert 一行 dsh-vim，让 Loader 挂载本插件
├── dsh.plugin.json     插件管理器展示用的清单
├── lib/
│   ├── index.js        Host 面：空壳 apply，只为让这一行能挂上
│   └── client.js       浏览器面：全部逻辑
└── tools/
    ├── selftest.mjs    假 DOM + 虚拟时钟驱动真实 client.js 的行为断言
    └── probe.patch.yml 不落盘的合成验证 overlay
```

没有构建步骤：`lib/` 是手写的、可直接运行的 JS。设置页用 `react` 的 `createElement` 手写，不引入 JSX 或 UI 组件库；任务窗是纯 DOM + 内联样式，零依赖，并且能被假 DOM 直接断言。

## 已知限制

- **「Enter 做什么」默认是「发送」，也就是不改宿主行为**。只有你主动切到「换行」/「什么都不做」/「连按两下 Enter 发送」，裸 Enter 才不再发送，且此时输入框下方会常驻一句淡灰提示写明发送键。
- **提示挂在宿主给输入框预留的那一行里**（`conversation.composer.dock` slot）。宿主换了名字、或者干脆没有这一行，提示就没了——但插件的其他部分照常工作，Enter 换行照旧生效，只是不再提醒你按哪个键发送。
- **「什么都不做」这一档下，`Enter` 在输入框里彻底不做事**——不发送也不换行。输入框里能换行的只有 `Shift+Enter`。
- **双 Enter 档占用了"连按两下 Enter = 空一行"这个手势**：想空行得换条路走。两条都行：**连按两下 `Shift+Enter`**（最快，完全不用掐时间），或者**两下裸 Enter 之间停超过 250ms**。这是这一档唯一真实的手感代价。
- **双 Enter 档的误发是不可逆的**。`Ctrl/⌘+Enter` 猜错的代价是"没发出去"，双 Enter 猜错的代价是"发出去了"。250ms 是取"够快能顺手按两下、够慢不至于把空行按成发送"，但它不是万能的——这也是它出厂不默认、并且四档里排最后的原因。
- **双 Enter 的第一下会往草稿尾部留一个换行**。宿主发送时会 trim 掉，所以正常看不到；万一某个版本不 trim，消息尾部会多一个空行。插件不主动删它——那意味着去改用户的草稿，代价比一个空行大得多。
- **焦点落在 iframe 内**（侧边栏浏览器、HTML 预览）时收不到按键，按键事件不会冒泡到父窗口。指针停在 iframe 上时命中测试只能拿到 iframe 这个元素本身，于是往上落到承载它的窗格。
- **「不自动聚焦输入框」只认富文本输入框**。普通 `input` / `textarea` 一律不管。换个把输入框做成 `textarea` 的宿主，这条规则会失效（滚动本身不受影响）。
- **空格进输入框靠 `COMPOSER_SELECTOR`**（`[data-lexical-editor="true"]`，Lexical 自己打的标记）或**已经见过一次的那个元素**。宿主换了编辑器又没打标记时，页面刚打开、输入框还没被聚焦过的那一小段时间里空格可能没反应；先点一下输入框就记住了。
- **「空输入框」的判据是编辑器根元素的文字为空**，所以附件不计入：只放了附件、一个字没打时，空格仍然会离开输入框。
- **计时只从"插件看到的那次开始"算**。起点超过 12 小时就不认，等下一轮开始时恢复。
- **任务窗第一版只有列表**，没有搜索框，也没有分组和置顶。列表超过 20 条的旧对话暂时翻不到。
- **弹窗的 12 小时窗口和 20 条一批是写死的常量**（`PALETTE_WINDOW_MS` / `PALETTE_LIMIT` / `PALETTE_STEP`），没有做进设置页。按理说这三项是最该暴露给用户的 tunable。
- **切换对话走 `uiWorkspace.openSession(id)`**，它同时用于侧边栏面包屑，所以从任务窗切过去和点侧边栏的观感一致。但它只切主视图，侧边栏的展开状态由宿主自己维护。
- **重命名走 `sessions.using`**，它会把那条会话短暂 retain 并打开一次（加载历史），然后立刻释放。所以给很久没打开的对话改名会有一点加载开销。
- **文件夹标签依赖宿主发布 `workspaces` 注册表**，而且依赖它给每条会话标好归属。没有注册表就整格不显示，不是显示错误的名字。
- **推理等级只改当前这一条对话**，不改"新会话的默认"。而且只能从宿主公布的档位里选——适配器没公布等级的模型，`q` 只能提示一句。
- **推理等级只走"当前屏幕上那条对话"**（按 `mainView` 保留关系认，和 Esc 的保护判据同一个）。侧边栏里没打开的那条改不到。
- **换模型会在下一条请求前插一条宿主自己的提示**（`[model changed: …]`），而且切换可能减少提供方侧的缓存复用。插件改不了这一条，但知道它存在才不会被它吓一跳。
- **常用模型清单是全局的**，不分对话，也不跟着账号走（存在 `localStorage`）。换台设备要重勾一次。
- **模型窗的外观跟着任务窗的字体大小走**（`paletteFont`），宽度、高度、行距、弹出位置这四项它不吃——那四项是任务窗自己的，模型窗是固定的小卡，居中弹出。
- **模型窗开着时任务窗打不开**：`f` 被模型窗吞掉。两个窗不叠加（宿主里没有这种用法，叠起来键盘归谁说不清）。
- **模型窗里没有搜索框**，清单多长就列多长。清单是手勾的，通常只有几个。
- **档位只在模型窗里能改**：`Tab`（`modelLevelKey`）只在窗开着时有意义，窗关着时它是普通字符。想不弹窗换档位还是用 `q`。
- **档位标记不做逐行记忆**：`Tab` 改过的档位属于你正停在的那一行，移到别的行就丢掉。一次选择、一次确定。
- **不公布档位的模型无法指定档位**：行上显示「无档位」，`Tab` 只提示一句，`w` 只切模型。
- **设置页的常用模型列表只在打开那一页时读一次目录**。目录读失败会给一个「重读」按钮；换模型、换账号之后不会自己刷新。
- **切换后不聚焦输入框**（默认开）。关掉这一项，就退回宿主的行为：三个时刻光标都会被塞进输入框，Esc 是你唯一的出路。
- **不注册进 `ctx.shortcuts`**，因此不出现在「快捷键速查」里、也不参与它的冲突校验。代价是换来了裸字母键在 Desktop 原生键盘桥接下不被抢占。
- **只支持单字符键**，不支持 `Ctrl+D` 这类组合键。
- **归档走宿主的 `uiWorkspace.archiveSession`，而且刻意不带 `stopActivity`**。所以**正在跑任务的对话按 `g` 不会归档**，只会提示你先停。这是有意的：带上那个参数，一个按键就能停掉你根本没打算停的任务。插件也不提供"归档并停止"的组合键。
- **归档没有撤销键，也没有确认框**。`g` 一按就归档（宿主自己的动作），和手动归档一样不可逆；要找回来得走宿主自己的「已归档」入口。没有确认框是因为任务窗里那几行本来就是"选中 + 一个键"的节奏，加一层确认会把它打断——但这也意味着**误按 `g` 没有回头路**。
- **归档的是屏幕上那条时，主视图会跟着清空**。这是宿主 `archiveSession` 自己的行为（它会把 `mainReference` 清掉），插件没插手，也拦不住。
- **`g` 只在任务窗里有效**。它是窗的键，不是页面的键——想归档哪条，先 `f` 开窗选中它。
- **任务窗或模型窗开着的时候 `e` / `d` 归它**。想两者同时拥有，就把任务窗的上下翻键改到 `j` / `k`，`d` / `e` 会落回页面（两个窗共用这一对键，所以改一次两处都跟着变）。
- **改动 `lib/client.js` 后需要重启进程**，运行中的模块版本不会热替换。
- **任务窗只在这次打开期间常驻**：刷新页面、重载插件、重启客户端都会把它收起来，需要再按一次 `f`（和计时不同，计时会落盘）。
- **阶段是手动标的，不会自己变**。这一版没有任何自动判断——对话该进哪个阶段由你点那个词（或按 `s`）决定，插件不会替你猜。自动化的入口是那个词表（`PHASES`）和账本（`PHASES_MODEL`）：新增一个来源（goal 投影、Agent 自己写的标记）只要往账本里写同一个词，这一格和存储都不用改。
- **标注只在这台浏览器里**。阶段落在 `localStorage`，跟着设备走，不跟着账号走。
