# dsh-vim

用键盘完成整个操作流程的插件，适用于 DeepSeek Harness Web / Desktop 客户端。

滚动、切会话、进输入框、退出输入框、改推理等级、换模型、重命名、归档、决定 Enter 发不发——每一步都有键。整个流程不用把手放回鼠标。

## 一条规则支撑全部

插件只做一件事：**保证每一颗键在任何时刻都是活的。**

宿主会在四个时刻把光标塞进输入框：首次打开页面、切换对话、**发完一条消息**、一轮任务跑完。每次落地，`d` / `e` / `f` 都变成死键，必须先按 Esc 才能滚。

本插件挡住了这四次。规则很简单：**输入框只在你要的时候才拿焦点。**

- 你点了输入框、按了 `Tab`、或者按了 `空格`——你**要**它，插件不插手。
- 宿主自己塞进去焦点——插件**立刻还给页面**，`d` / `e` / `f` 当场可用。

这不是"切换后 600ms 内的守卫"，是常驻规则。不管宿主的焦点来得多晚，只要不是你主动要的，就进不去。

挡住的只有富文本编辑器（这个宿主里就是消息输入框）。设置页、侧边栏搜索这些面板自己聚焦自己的字段，是面板的事，插件不碰。

这条规则是其余功能的前提。没有它，`d` / `e` / `f` 在最常见的三种情况下都是死的。

## 键位与功能绑定

这是本插件唯一的核心对照表。所有键都能在设置页改。

### 页面上的键（任务窗关闭时）

| 键 | 绑定功能 | 配置项 |
|---|---|---|
| `d` | **鼠标指着的那个窗格**向下滚动 | `downKey` |
| `e` | **鼠标指着的那个窗格**向上滚动 | `upKey` |
| `空格` | 进入输入框。**空着时再按一次 = 离开** | `focusKey` |
| `q` | 推理等级换下一档，循环。**只动等级，不动模型** | `effortKey` |
| `w` | 弹出模型选择窗；**窗内 = 确定切换** | `modelKey` |
| `j` | 打开**看板画布**（侧边栏「看板」是同一个入口）：一块地方一个**目标**（默认用工作区名，可自己改），会话排在下面，分叉有连线，空白处能写想法卡片；卡片行首带状态标签（进行中 / 等你 / 刚刚完成）。再按一次回到对话 | `boardKey` |
| `n` | **给当前对话记一条想法**：打开看板，把光标放进当前对话那张卡的想法框。Enter 记下，Esc 放弃，点别处也记下 | `noteKey` |
| `i` | **把屏幕上这个对话放到看板**：给它盖上「收藏」，于是隔了夜、停了工也还在看板上。任务窗开着时，这一下作用在**选中的那一行**上 | `pinKey` |
| `Enter` | **在输入框里**：发送 / 换行 / 什么都不做 / 连按两下发送，四选一 | `sendMode` |
| `Ctrl/⌘+Enter` | 发送（**宿主自己的键**，任何档位下都有效） | — |

### 任务窗里的键（窗口打开时）

| 键 | 绑定功能 | 配置项 |
|---|---|---|
| `f` | 打开任务窗 / **窗内 = 前往选中的对话**（站在 `更多` 上时 = 展开下一批） | `paletteKey` |
| `e` | 上移选中项 | `paletteUpKey` |
| `d` | 下移选中项。走到 `最近` 区末尾会**停在 `更多` 上**，再按一下才回绕到第一条 | `paletteDownKey` |
| `r` | 重命名选中的对话（站在 `更多` 上时什么都不做） | `paletteRenameKey` |
| `s` | 切换选中对话的**阶段**（讨论 / 编码 / 检查）（站在 `更多` 上时什么都不做） | `paletteStageKey` |
| `g` | **归档**选中的对话（站在 `更多` 上时什么都不做） | `paletteArchiveKey` |
| `o` | 前往选中的对话（站在 `更多` 上时 = 展开下一批） | `paletteEnterKey` |

### 模型窗里的键（窗口打开时）

模型窗复用任务窗的上下翻键，所以 `d` / `e` 在窗里是同一件事：

| 键 | 绑定功能 | 配置项 |
|---|---|---|
| `w` | **确定**，切到选中的模型（和它标着的档位）并关窗 | `modelKey` |
| `e` | 上移选中项 | `paletteUpKey` |
| `d` | 下移选中项。走到末尾回绕到第一个 | `paletteDownKey` |
| `Shift`+`e` / `Shift`+`d` | **把选中的那一行换个位置**（记住顺序） | 跟随上下键，无独立配置项 |
| `Shift`+`↑` / `Shift`+`↓` | 同上，方向键的固定别名 | — |
| `Tab` | **换档位**：下一档，到头回绕；`Shift+Tab` 是上一档 | `modelLevelKey` |
| `q` | 同样换档位，`Tab` 的另一个入口（同一档位，不另选键） | `effortKey` |

`Shift`+上下键的调顺序和上下键本身共用一套键：同一个动作加个修饰键。改了上下键的绑定，调顺序也跟着走；没有第二组键位要记。**到头不回绕**——把一行挤到列表外面去不是「换一个位置」的意思，所以移不动就不动。

不可改的键：

| 键 | 说明 |
|---|---|
| `Enter` | 窗内确认的常驻别名。改掉切换键之后仍然可用，也不许被别的座位占用 |
| `↑` / `↓` | 窗内移动选中项 |
| `←` / `→` | 窗内换档位，和 `Tab` / `Shift+Tab` 同一个动作 |
| `Esc` | 窗内唯一的取消键。**永远能关掉窗口**（点窗口外面同样能关） |
| `Esc` | 输入框里：焦点交还页面。行为可关 |

**`Tab` 在模型窗里是档位键，不再移动选中行**（0.17 起）。移动选中行用 `d` / `e` 或 `↑` / `↓`。把 `modelLevelKey` 改到别的键，`Tab` 就退回它原来的「下移选中项」——不会变成一个什么都不做的键。

### `d` / `e` 的三个意思

`d` 和 `e` 在两组里都出现，这是故意的：

- 任务窗和模型窗**都关着**时：`d` / `e` = 滚动页面
- 任务窗**打开**时：`d` / `e` = 移动选中行
- 模型窗**打开**时：`d` / `e` = 移动选中项（和任务窗同一组键）；`Tab` / `q` = 换档位

**再加一个 `Shift`**：模型窗里 `Shift` + 上下键 = 把选中的那一行换个位置。它只在模型窗里有意义，任务窗和页面上 `Shift+d` 什么都不是。

窗口开着时键盘归窗，鼠标停在哪里都一样。所以 `f` → `d` `d` → `f` 这一套不会因为手边鼠标的位置而变意思。

两个窗不会同时认领键盘：模型窗开着时按 `f`，`f` 被模型窗吞掉，不会在它后面再开一个任务窗。想先挑模型再挑对话，就 `Esc` 掉一个再开另一个。

同一组内不许重复，跨组随便撞。

### 焦点在输入框里时

插件**完全不介入**。`d` / `e` / `f` / `q` / `w` 都是普通字符，用来打字。

唯一的例外是聚焦键（默认 `空格`）：**输入框里一个字都没有时，它把焦点还回来**。有内容时它还是普通的空格。焦点停在按钮上时空格仍然是"按下这个按钮"，插件不抢。

### 发完一条消息之后

按 Enter 发送的那一刻，插件会把焦点交还页面，`d` / `e` / `f` 当场可用——**按 `f` 打开任务窗时，它不会变成往草稿里打的第二个字**。想接着写下一条，按一下聚焦键（默认 `空格`）就行，**草稿一个字都不会少**：这里只挪焦点，从不碰文本。

为什么需要这一条：输入框在发送前后始终保持着 DOM 焦点，宿主再调一次 `focus()` 是个空操作，**根本不会触发 `focusin`**。所以「拦住宿主塞进来的焦点」那条常驻规则在这里无从下手——插件只能自己发一次 `blur()`。

判定为"一次发送"的条件（缺一不动）：焦点在消息框里 · 不在中文输入法组字中 · 候选列表（`/` 菜单、`@` 菜单）没开 · 输入框非空 · 按的是裸 `Enter`（`Enter` 设置为"换行"或"什么都不做"时不算，那两种模式下只有 `Ctrl` / `⌘` + `Enter` 才发送；设置为"连按两下 Enter 发送"时，第二下 `Enter` 算）。

探测排在 `0ms` 和 `120ms` 两处，避开宿主自己处理发送的那一拍；这两处都不碰文本，猜错的代价只是"你得再按一次空格"。期间只要你自己要了键盘（点一下、`Tab`、聚焦键、开始打字），交还立刻作废。

**点发送按钮这条路本来就没这个问题**：按下按钮时 `pointerdown` 已经作废了那张"用户要键盘"的通行证，宿主随后塞进来的焦点会被老规则直接弹回去。

### 四个焦点开关

在设置页里，不占键位，四项默认都开：

| 开关 | 作用 |
|---|---|
| 不自动聚焦输入框 | 宿主塞进来的焦点立刻还给页面 |
| 发完消息交还键盘 | 消息发出去的那一刻，焦点还给页面 |
| 空格离开空输入框 | 空输入框里再按一次空格 = 离开 |
| Esc 离开输入框 | 输入框里按 Esc = 离开 |

## 键盘流程

### 滚动

按 `d` / `e` 时，插件先问一件事：**你现在鼠标指着的是哪一块？** 然后滚那一块。

| 鼠标停在 | `d` / `e` 滚的是 |
|---|---|
| 对话正文 | 对话内容 |
| 侧边栏 | 会话列表、文件树，以及侧边栏里任何可滚的部分 |
| 右侧栏 / 插件面板 | 那一块自己的内容 |

具体判法：从鼠标位置取一个元素，沿着它往上找，找到第一个「能滚」的元素就算数。判「能滚」的条件是：CSS 的 `overflow` 是 `auto` / `scroll` / `overlay`，并且内容确实比容器高。

所以它不认「这是侧边栏」「这是正文」这种标签。**它只认「这块现在能滚」**。这也是侧边栏不需要专门代码的原因。

判定顺序：

1. **鼠标指着的窗格**——绝大多数时候走的路。
2. **焦点所在的窗格**——鼠标还没动过（纯键盘操作），或者鼠标停在滚不动的地方（窗格标题、两栏之间的缝）。此时回退到正文。
3. **窗口正中间**——正文。
4. **页面上最大的可滚容器**——最后的兜底。

细节：

- 鼠标位置只在**按下 `d` / `e` 的那一刻**读一次。单独移动鼠标不会滚动任何东西。
- 按住不放时把鼠标移到另一块，剩下的连发跟着换过去。
- **并列的块不接力**：侧边栏滚到底不会跑去滚正文。但**嵌套的块会向上接力**，和滚轮一样——内层列表到了头，外层面板接着滚。
- 窗口失焦后不再使用记下的鼠标位置。浏览器在别的窗口处于前台时不派发鼠标移动事件，那个位置可能是旧的。
- 插件里**没有任何写死的选择器**。

### 输入框：空格进，空格出

聚焦键不只是"进去"。**输入框里一个字都没打的时候，再按一次就出来**——焦点还给页面，`d` / `e` / `f` 立刻可用。进出同一个键。

判据只有一条：**编辑器的文字是不是空的**。这正是宿主自己判断"要不要显示占位提示"用的那条（`draft === ""`）。

- **空**：按下去 = 离开。空编辑器读出来就是空白（Lexical 的空段落是一个换行符），所以这里不看 DOM。
- **有内容**：还是普通的空格，该打字打字。`@` 提到的文件在草稿里是一个引用字符，同样算内容。
- **只有附件、没有文字**时算空。附件不在编辑器的文字里。
- 按住不放不会来回切。第一次按下离开，后面的连发什么都不做。

为什么需要它：**Esc 不总是能用**（见下节）。这时候空格就是唯一的出路。

### Esc 和输入框

宿主自己的 Esc 逻辑是：关掉候选气泡 → 问一句"这次转写要不要中断" → 被消费就到此为止，**它从不把焦点还回来**。所以常见情况下这个键是空放的，插件接管了它。

- 在输入框里按 Esc → 焦点交还页面，`d` / `e` 立刻恢复。
- **不让宿主的 Esc 失效**。插件在**冒泡阶段**才动手，等宿主先处理。宿主已经处理过就让路。
- **正在跑的任务，Esc 完全归宿主**。宿主用 Esc 中断当前转写，而且中断时不标记事件已被处理，所以让路机制看不见它。这种情况下插件**什么都不做**——一次按键毁掉一个你根本没打算停的任务，是最坏的一种意外。
  - 只看**当前屏幕上那条**在不在跑。后台别的对话在跑，不影响。
  - 宿主没发布状态源时，退回目录里的 `running` 布尔值，照样保护。

四条焦点规则互相独立：**空格**是你让输入框进来（空的时候也是你让它出去），**Esc** 是你自己出去，**不自动聚焦**是插件不让宿主硬塞，**发完交还**是消息一出去就把键盘还回来。

**剪贴板工具（Ditto 之类）是例外的一条**。它们不点输入框，而是把窗口切回前台、然后**自己按 Ctrl+V**——光标必须在那一瞬间已经在输入框里。所以**窗口刚拿回前台后的 400ms 内**，输入框得到的焦点算你的，插件不收回；过了这 400ms 的、或者不是紧跟着切回来的焦点，照旧一律还给页面。控制台里 `palette()` 不受影响，这条规则只动焦点。

### 任务窗

按 `f` 弹出一个浮层，列出可以切回去的对话。**选好之后再按一次 `f` 就过去了**——开窗、选人、跳过去，同一个键按两下。

**顶上先答"有什么在等我"，再答"东西都放在哪"**。窗口的排序轴不是文件夹、也不是新旧，而是**谁在等你**：

```
2 条等你 · 3 条在跑                    ← 标题是一句话，不是条数
球在你这边                             ← 等你动手的，按等得最久的排在最上
  等待批准  api-service  部署审批 · 4 分      ← 状态在最左，先答"它怎么了"
  刚刚完成  dsh-vim      aaa · 2 小时前
进行中                                 ← 在跑的，弱化显示，不需要你
  进行中    dsh-vim      bbb · 1 小时前
最近                                   ← 近 3 小时的，按时间倒排
  web      重构登录页 · 1 小时前
  dsh-vim  ccc · 2 小时前
更多 · 18                              ← 更早的，要展开
```

3 小时内整个池子都没有活动时，第一块不叫 `最近` 而叫 `更早`，装的是最新的一批：

```text
更早                                   ← 3 小时内没有活动，这是回填的历史
  web      重构登录页 · 3 天前
  dsh-vim  bbb · 4 天前
```

**为什么轴换了**。窗口原来按"这条对话住在哪、有多新"排，可你打开它想问的是"有没有东西卡在我这儿"。这条信息原来在每行最右边一小格里，于是必须逐行扫。现在它决定位置：**卡住的排最前，跑着的排中间，近期的按时间倒排垫底**。

- **`球在你这边`**：等你批准 / 等计划审阅 / 等回答，**以及跑完了你还没看过的**（`刚刚完成`）。前三种是你欠它一个决定，第四种是你欠它一次查看——都是球在你这边的。
- **`进行中`**：有 turn 在飞，不需要你。它被**弱化**（整行降透明度，不是变灰到看不清），因为这一块是背景音，不该读成一排要求。
- **`最近`**：近 **3 小时**内动过的对话，**按时间倒排**，一行一条。3 小时而不是一天：这一块回答的是"我刚才在忙什么"，比一个工作日更早的东西不是那个，是历史——历史归 `更多`。**窗口按整个候选池算**，正在跑的和等你处理的也算数（它们本身就是"刚发生的事"），所以一个忙着的下午不会因为"挑剩下的都是旧的"而误判成安静。
- **`更早`**：只有在最近 3 小时**整个池子**都没有活动时才出现，代替 `最近` 显示最新的一批，避免开一个空窗。它叫 `更早` 而不是 `最近`，因为这时它装的确实是历史。
- **前两块从**整个候选池**里取，不受 3 小时窗口和 20 条上限约束。** 一条昨天就卡住的对话必须浮上来——按时间窗口切的话它会被切进 `更多` 里，最该看见的反而被藏得最深。
- **一条对话只出现一次**。被上面两块收走的行**从 `最近` 里拿走**，不会重复出现，也不占 `最近` 那 20 条的额度。
- **`球在你这边` 内按"等得最久"排**。等得久的在最上，不是最新鲜的在最上。窗口没亲眼看到它开始等的那一刻（比如页面加载时它就已经在等了），就退回用最后活动时间兜底——不编一个起点出来。

**标题能说"没事"**。没有任何东西等你、也没有东西在跑时，标题直接写 `没有要你处理的`。一个能明确告诉你"可以关掉我"的窗口，和一个只会显示 `12 / 46` 的窗口，心理负担不一样。这句话**只陈述它看得到的事实**——它出现的那一刻恰恰什么都没在跑，所以它不说"都跑着呢"。

**开窗时选中的是"第一个在等你的"**（没有才退回选中你此刻所在的那条）。这条让**处理完一条，下次开窗自动指向下一条**——不用记位置、不用加键、不用标已读。

**开窗时 `刚刚完成` 的标签会动一下**（约 0.76 秒，一次）。`球在你这边` 里前三样是「等你决定」，`刚刚完成` 是唯一只要「看一眼」的——它没有决定要下，却最容易在整行里被忽略：一个淡蓝色小词，夹在名字和阶段之间，和旁边那些等你处理的字长得一样重。这一下让眼睛在头半秒落到它上面，然后归位，**不在行上留任何标记**——不用清理，也不用标已读。只在开窗那一下触发（窗口开着时的刷新不会重放）；**`prefers-reduced-motion: reduce` 下完全不播**——这个标签本身已经把事实写在字上了。

**文件夹是每行上的一个标签，不是一个容器**。这一版把原来"一个文件夹一块、块标题写文件夹名"的结构**拆掉了**：现在每行行首带一段淡灰的文件夹名，列表整体按时间倒排。

- **为什么拆**：块是"先到先得"地吃 20 条额度的——按文件夹顺序一块一块填，**忙的文件夹能把额度吃光，让另一个文件夹一条都露不了面**，哪怕那个文件夹里装着整张列表上最新的对话。拆成一行一条、按时间排之后，这个饿死问题从结构上就不存在了。
- **代价**：文件夹名从"一块说一次"变成"每行说一次"。这是有意的取舍——标签便宜，而按块分组的顺序错了会更贵。
- **没有 `workspaces` 注册表时**：每行没有前缀，列表照旧按时间倒排，不是坏掉。

**标题行不是行**：`d` / `e` 从它身上走过去，`Enter` 不会"切换到某个标题"，点它也什么都不做——**唯一的例外是 `更多`**（见下）。

**`更多` 既是按钮、也是能走到的一站**。`d` / `e` 走到 `最近` 区最后一行再往下，就**停在 `更多` 上**（它会高亮，和选中一行一样）；再按一次 `d` 就跨过它落到下一行，按到头回绕。站在它上面按 `f` / `o` / `Enter` 就是展开——**展开动作没有变，只是键盘现在够得着了**。0.18.2 之后纯键盘用户到不了第 20 条以后，这一站就是补这个洞。

- **站在 `更多` 上时，那些操作对话的键（`r` 改名、`g` 归档、`s` 阶段）什么都不做**，不会顺手作用在它上面那一行。站在一个"还有更多"的座位上，却把上面那条对话改了名，是这类双关游标最容易出的错。
- **点它不动选中项**。列表在你选中的那一行下面变长，选中的还是原来那条。
- **没东西压在下面时它不再是可站的一站**：指针不变手形，`d` 也不再停上去，它退化成一行普通标题。展开完最后一批时，光标会落到刚展开的第一行上，不会留在一个已经不存在的座位上。
- **为什么不让 `d` 顺手带出来**：一个会改变列表长度的键，结果没法预测；而"还有多少"已经写在屏幕上了，要不要再往下挖，是一次决定，不是一次路过。**走到座位上不等于展开**——这是"能到达"和"替你决定"的区别。

**对话名是淡的，文件夹名更淡**。名字的透明度是 `0.72`，前面那段文件夹是 `0.5`——一屏名字全用满权重就没人会去扫，而文件夹是限定词，比名字本身更该退到后面。这两层透明度**分别挂在各自的元素上**，不是挂在外层单元格上，所以它们不会叠乘。

**状态在最左，名字紧跟其后，其余退到右边**。一行从左到右是：`状态` → `文件夹名 + 对话名` → `当前` → `阶段` → `轮数` → `时间`。

- **状态为什么放最左**：这个窗回答的第一个问题是"有什么在等我"，块标题已经按这个切过一次，每一行也该在**同一侧**再答一次。状态原来在最右，眼睛要先跑到行尾才读到它，再倒回来找名字——阅读方向和注意力方向是反的。放最左之后，每行从左边开始就是"状态 → 名字 → 细节"，一个方向读完，不用回扫。
- **名字还在同一列起头**：状态占一列固定宽度（按屏幕上最宽的那条状态拟合），所有行名字都从同一个 x 开始，`最近` 里没有状态的行也照样留这段空槽——跨块对齐比省那点宽度值。
- **`当前` 留在名字后面**：它标记的是"这一行就是我"，属于身份的一部分，不是要去右边找的细节。
- **脉冲也只打在左边**：开窗时 `刚刚完成` 那一拍落在每行的第一个落点上，紧接着就是名字。

**顺序只为能记住而存在**。开窗时选中的是第一个等你的（右侧挂一个紫色的 `当前` 标签表示你在哪），但每行**留在它本来的位置上**——列表不为"你所在的那条"重排。

这一点是整件事的目的：以前每次切换对话，那条对话都会被搬到第一行，于是"第三行是谁"这种位置感每切一次就失效一次。现在顺序只由"谁在等你"和时间决定，切换对话不改变它，你才学得会这一屏。

`当前` 是独立的一格，排在名字**后面**——它说的是"这条是哪一条"，属于这一行的身份，所以紧跟名字，不占对话名的地方，也不会被长名字挤掉；反过来，对话名也不再被一个前缀吃掉，所有行的名字都从同一个位置开始。那条对话不在列表里时（比如它被归档了），**这一格整列收起来**，不给其余行留一条空边。

每一行是**六格**（状态、对话名、`当前` 标签、阶段、轮数、时间），**状态是第一格，对话名是第二格**。

这六格中状态那格按屏幕上最宽的一条状态拟合、**贴着自己那一列的左边**（所有状态词从同一个 x 起，名字也从同一个 x 起）；`当前` 和右边三格（阶段、轮数、时间）各按最宽的一格算、**贴着自己那一列的右边**。不这么做的话，每行会各按各的内容排，`13 轮` 和 `刚刚完成` 就会一行的位置一个样。计时变长（`59 分` → `1 小时 0 分`）时会重新量一次那一列，所以数字长大不会挤到名字。对话名列吃掉剩下的宽度，多出来的一律省略号。

**阶段**说的是**这一轮在讨论、编码还是检查**——回答"这件事现在做到哪了"，而下面那个状态回答"它现在跑没跑"。两者不是一回事：一条对话可以正跑着编码，也可以跑完了等你验收、状态显示`刚刚完成`而阶段停在`检查`。

这一格**把三个词都摆出来**，当前那个高亮：

```
讨论  编码  检查        ← 未标注：三个都是灰的
讨论 [编码] 检查        ← 标注后：当前那个亮起来（这里用方括号示意）
```

- **点一个词就标上**。不用先知道有哪些选项、也不用记顺序——每一行都把整份词表摆在你眼前。
- **点已经亮的那个 = 取消标记**。所以"怎么摘掉"不需要多余的说法，亮的那个就是回头路。
- **点词只改阶段，不会跳到那条对话**（行的其余部分才是切换）。
- **窗内按 `s`** 按同样顺序推进：讨论 → 编码 → 检查 → 未标注 → 讨论。键盘用户走这条路，看到的东西和点的一样。
- 标注**跟着对话走**：关掉任务窗在，刷新页面在（存在 `localStorage` 的 `dsh-vim/phases/v1`）。
- 这一版标注是**你自己点上去的**。阶段这个词表是插件自己的，不绑定任何宿主投影——将来要让它自己判断（读 goal、读 Agent 写的标记），只要往这个账本里写同一个词表，这一格和存储都不用动。

**状态标签**告诉你这条对话现在在干什么：

| 标签 | 含义 |
|---|---|
| 等待批准 / 等待计划审阅 / 等待回答 | 卡在需要你动手的地方 |
| 进行中 | 正在跑（模型或子代理） |
| 刚刚完成 | 跑完了，而且你还没去看 |
| （无标签） | 空闲 |

优先级和侧边栏一致：**等你 > 在跑 > 刚完成**。状态会实时更新，它跑完的那一刻标签就变了，不用重开弹窗。

**正在跑的带一个计时**，写在状态标签里面，比如 `进行中 · 3 分`。等批准、等回答也算在飞的这一轮。它只改那一块标签的字，不重画列表，所以你正在选的行、正在改的名字都不会被打断。

- **只到分钟，不到秒**。以前是 `3 分 20 秒` 而且每秒自己走；现在满一分钟才出现，之后每分钟走一格。改的原因不是省开销，是**秒级的数字会把一屏在跑的对话变成一排同时跳动的脉搏**——那正是"好几件事在飞、一件也抓不住"的感觉本身。分钟级照样回答"这件事跑了一阵了"，但不再是一个盯着看的数字。
- **不满一分钟不显示时长**，只留 `进行中`。一个每看一眼都不同的数字是在邀请你一直看它，而这一分钟里没有任何值得读的时长。

计时是怎么来的：宿主**没有发布开始时间**（状态里只有 `running` 布尔值，会话摘要里一个时间戳都没有），所以插件自己盯着状态源，**从页面启动就盯着**，看到某条会话从"不在跑"变成"在跑"就记下那一刻。因此窗口什么时候开的都没关系，十分钟前开始的任务就显示十分钟。

**起点会落到 localStorage**（`dsh-vim/runs/v1`），所以刷新页面、重载插件、重启渲染进程都不会把计时打断。

拿不到起点的情况只有两种：这是这个浏览器**第一次**见到这条会话在跑（换了设备、清了存储、或者起点超过 12 小时），或者这一页已经开了一分多钟而那条会话才第一次出现。这两种都**不显示计时**，只留「进行中」。编一个起点出来不如不显示。**等你的那两块也用它排序**：起点在就按它排（等得最久的在最上），没有起点就退回用最后活动时间，一样不编。

**轮数**（比如 `13 轮`）不在会话列表里，宿主只把 `title` 放进列表，所以要单独去问：

- **弹窗不会等它**。窗口瞬间就开，轮数后到，来了自己填上去。
- 一次最多同时问 3 个，单个最多等 1.5 秒，超时就不显示。
- 按 `会话 + updatedAt` 缓存，对话没动过就不会重复问。
- 读不到、宿主没这个投影、或者抛异常——一律不显示，也不重试。

列表**不贪心**：

- **已归档的不展示**。
- **空的占位会话不展示**——那是"新对话"的临时槽，切过去是空的。
- **`最近` 打开时只给最近 3 小时的**，按时间倒排，最多 20 条。**当前对话不受这个限制**：它在窗口外面时会被拉进来，而且拉进来之后**留在时间序里**，不是追加到末尾。
- **`球在你这边` 和 `进行中` 不受这两个限制**：它们从整个候选池里取，一条昨天卡住的对话也会浮上来；而且它们**不占** `最近` 那 20 条的额度。
- **更早的要点一下 `更多` 才展开**，每次多 20 条，全部收在同一个`更多`标题下面——那一块回答的是"还有多少"，不是"属于哪个文件夹"，所以不分文件夹。`d` / `e` **会走到 `更多` 这一站上**（再按 `f` / `o` / `Enter` 展开），但**不会替你展开**。
- `更多` 右边的数字是**还压在下面的条数**，不是已展开的条数；展开完了数字消失，它也不再是可站的一站。还没有东西压在下面时，这个标题整行都不出现。
- **3 小时窗口按整个候选池算**，不是按"被上面两块挑剩下的那些"算。正在跑的那条、等你批准的那条，本身就是这 3 小时里发生的事——把它们先拿走再判断"有没有新鲜事"，会让一个明明很忙的下午被读成安静的下午，然后触发下面那条回填。
- 最近 3 小时一条都没有时，退回显示最新的一批，不开空窗；但**块标题会改成 `更早`**，不叫 `最近`——这一块回答的是"我刚才在忙什么"，回填的答案恰恰是"没什么"，标题必须说这件事。`palette().stale` 能读出当前是不是这种回填状态。

**重命名**：窗内按 `r`，选中那行的标题变成一个输入框，原标题整段选中。`Enter` 确认，`Esc` 放弃。

- 提交前去掉首尾空格。只有空格的名字会被拒绝，框留着让你改。
- 名字没变就直接收起输入框，不白跑一趟宿主。
- 失败会说话：宿主的拒绝理由显示在底栏，输入框不关，名字不丢。
- 重命名不导航。确认后窗口还开着，想过去就再按 `f`。
- **编辑期间键盘完全归输入框**：`d` / `e` / `f` 都只是普通字符，不会翻列表、不会跳走、也不会关窗（点窗口外面关窗不算——那是你主动去点别处了）。

**归档**：窗内按 `g`，把选中的那条对话收起来。走的是**宿主自己的归档动作**（`uiWorkspace.archiveSession`），和你在侧边栏里手动归档是同一件事。

- **正在跑任务的对话不会被归档**。宿主本身就会拒绝这种请求（错误码 `workspace/session-active`，并列出在跑的是哪个 turn / job）；插件**故意不带** `stopActivity` 这个参数——带了就等于让一个按键替你停掉任务，而**一次按键毁掉你根本没打算停的任务，是最坏的一种意外**，这条原则和 Esc 完全一致。遇到这种对话，底栏会说「这条对话正在跑任务，先停下来再归档」，把决定权还给你。
- **归档没有撤销键**，但宿主自己的「已归档」入口能找回来。插件不替宿主做回收站。
- **窗不关**，方便连着归档几条；被归档的那行由宿主从列表里拿掉（插件自己不动列表）。
- **归档的正是屏幕上这条时，主视图会跟着清空**——这是宿主的行为，和手动归档一样。
- **失败会说话**：宿主的拒绝理由显示在底栏，那行留在原地，可以再试。
- **宿主没发布归档动作时**，`g` 会在底栏写明"这个宿主不支持归档对话"，而不是默默什么都不做。

**任务窗不模态、也不会自己消失**。按 `f` 打开之后它一直在，只有三样东西能让它消失：`Esc`、**在窗口外面按一下左键**、或者选中一条并切过去。打字、失焦、切标签页都不关。

**点窗口外面 = 关窗**，这是给不用键盘的路留的：

- **那一次点击照常作用在页面上**。窗的背板不接事件（`pointer-events: none`），所以点正文、点侧边栏、点工具条，页面该响应什么就响应什么，窗只是顺手从屏幕上消失——一次点击既看清了下面是什么，又把窗收了。
- **只认左键**。右键 / 中键要的是菜单，不该顺手把窗带走。
- **卡片内部点了不算**：标题、某一行、底栏、重命名的输入框都在窗里。
- **重命名改到一半点外面，窗关掉，改了一半的名字一起丢掉**，不会提交给宿主——和按 `Esc` 是一回事。
- **两个窗同时在页面上时**，按在其中一个的卡片里，两个窗都留着；按在两个外面，两个一起关。
- **点在 iframe 里收不到**，所以 iframe 内部（比如侧边栏浏览器）点不到窗外去，见「已知限制」。

**唯一的例外是窗自己没有认领的滚动键**。把窗的上下翻键改到别的字母上（比如 `j` / `k`），`d` / `e` 就不再是窗的键，落回页面去滚正文，窗照旧留着。想边读边挑就这样配。

### 看板：目标画布

看板是**主区域里的一页**，不是浮层：侧边栏「插件」「自动化任务」下面有「看板」，点它进页；`j` 是同一个入口（再按一次回到对话）。**从对话页回去还有一条鼠标路：在会话页里右键一下，就是回看板**——会话页自己的右键从来不做事（宿主的右键菜单全在侧栏的行上，会话正文上右键没有任何归属），于是这一下成了最短路。只有两处右键原样保留：**输入框里**（那是剪切/复制/粘贴的地盘）和**落在选中文字上**（那是复制）；侧栏、插件页、自动化页、各个浮窗都不受影响，判面用的是宿主自己的 `data-conversation-content` 标记。它是一张**画布**：每块地方是一个**目标**，会话卡片排在下面；空白处按住拖动是平移画布；**目标的标题整条都能拖**（含名字、计数，一路拖到底都算），卡片以外的纸面也算；**卡片自己**按下拖是卡片在动，这是同一条规则的两面。思路很简单——**F 弹窗回答"什么在等我"，看板回答"东西都在哪、哪些在跑、哪句话还没落进对话"**。

```
│  │ 重命名交互          ┌───┐│  │ 部署审批      ┌───┐ │  │
│  │ 备注：先问一句…     │ ⏎ ││  │              │ ⏎ │ │  │
│  │ 进行中·3分  ✎ ★ ×  └───┘│  │              └───┘ │  │
│  │                     ┌───┐│  │              ┌───┐ │  │
│  │   └ 分支 A          │ ⑂ ││  │              │ ⑂ │ │  │
│  └─────────────────────┴───┘┘  └──────────────┴───┘─┘  │

│                    │ 先问一句…  │                       │

└ 拖目标移动它 · 双击标题改名 · 拖会话卡片进另一个目标 ────┘
```

会话卡片**不分栏**：整张卡都是内容（标题、备注、信息行），信息行右端是一排小标记（轮数、`✎`、`★`、`⑂`、`×`）。**没有 `⏎` 按钮**——整张卡就是入口，那一栏本来只为一次很少发生的"拖入"而占着五分之一。

**这块地方叫「目标」**（`Goal`）。它一开始是**一个工作区**：名字就是工作区名，会话是今天动过的那些。但它不限定是工作区——**双击标题就能改名**（Enter 保存、Esc 放弃、清空就退回工作区原来的名字），日常用法是把它改成一个**你正在做的事**：`把登录改完`、`交付 HLD`、`重命名交互`。名字存在看板文档里，跟着这台浏览器走。**名字只是个标签**：一块目标靠两样东西留在画布上——**有会话在它下面**，或者**你给它写了那句 🎯**。两样都没有，它就在下一帧收起，位置和名字一起走。

**🎯 那一行是这块地方要做什么**（`intents`）。名字说这块地方叫什么，🎯 说要在这里做成什么：`周四前把登录页的错误提示改完`。点一下就写，Enter 保存、Esc 放弃、清空就是撤回。它长在标题下面、卡片上面，**折叠起来也还在**——一块折好的目标就是一张计划卡，计划在、会话收起来了。写完这一句，目标即使一条会话都没有也留在画布上；这也是唯一能让一块**还没有会话**的目标立起来的办法。

**目标是能自己立的**：顶栏 `＋ 目标` 在视野中间放一块空目标，🎯 行直接打开。以前目标只能由会话拖出来生出来，于是还没开工的事无处可写。这样立起来的目标算**草稿**：这一趟看板开着就一直留着（免得你打字打到一半它被自己的规则收掉），关看板时还没有会话、也没写 🎯 的，就跟看板一起收起。

**目标也是开新会话的入口**：标题右端有一个 `＋`。点一下弹出一个实心的对话框（不是一张半透明的便签），写标题和正文，按 `创建`——标题成为会话名，正文**不发送**：它作为草稿放进这条新会话的输入框，发不发由你按；新会话当场打开并记在这块目标下。**正文可以留空**：只写标题就只建一条会话，光标停在这条新会话的输入框里等你写。**还能选模型**：窗口里的「模型」一行默认跟着宿主走，点一下弹出 `w` 的那个模型窗——同一份常用模型清单、同样的行和档位键；选中即确认，会话建好后先把模型落到它上面，再把正文放进草稿，所以按发送时用的就是你选的那条。也可以把画布上已经写好的想法卡直接拖到这个 `＋` 上：卡片第一行当标题、整张卡作为草稿放进输入框，不再问第二遍；卡片留在原处，标成已完成并连到这条新会话。目标本身还没有工作区时会提示先在侧边栏开一条会话，不会把新会话扔进一个猜出来的地方。

**目标也能收起**：自己立的目标，标题右端有个 `×`。它不是删会话——这个目标里的会话**回到各自的工作区**（没有工作区的进收件箱），目标本身的位置、名字、🎯 一起消失，底下一行提示带 `撤销`，5 秒内点一下原样回来。工作区那一块**没有 `×`**：它是从会话派生出来的，收掉下次照样回来，一个会自己复活的删除键比没有更糟——它会话走光又没写 🎯 时自己就收起了。

**哪些目标出现**：今天有会话动过的工作区（按最近活动从新到旧）、标了 `★` 的会话所在的工作区、**有会话被拖进来的**、**写了 🎯 的**。**“被改过名”不再是留下的理由**：名字是标签，理由是会话或 🎯。**收件箱**单独一块，装的是**没有归到任何工作区的会话**（以及被标了 `★` 但没有工作区的）；它**不是目标**，见下面「托盘」一节。

**收件箱不是目标，是托盘（tray）**，所以它单独设计：

- **它装两种东西**：今天动过、还没有工作区归属的**会话**，以及你**收进来的想法卡**。目标只装会话——目标是"我在做什么"，托盘是"什么还没归位"。
- **它分两段**：`会话 N` 在上，`想法 M` 在下，各带计数。**托盘里两种东西用同一张纸**：会话卡换上和想法卡一样的暖色纸面（形状仍是会话卡），想法**收成一行**：一个方框、一句话、它的连线与删除（鼠标停上去才出现）。托盘是清单，不是纸面，一行才能一眼扫完；纸色相同是为了让这个面板读起来是**一个地方**，而不是两张表叠在一起。
- **怎么收进来**：把一张想法卡拖到托盘面板上松手（不要拖到会话卡上，那是连线）。它会从纸面消失，落进托盘变成一行，`filed` 记在卡片上；原位置保留，所以拖出来会回到原处。
- **怎么拿出去**：按住那一行拖出去，第一下移动它就变回一张纸跟着手走，松手落在哪就是哪。
- **它不能改名**：名字就是它的语义；双击标题不会出现输入框。它也可以折起来，标题上的数字是**两种东西的总数**。
- 一句话：**目标是"往哪去"，托盘是"从哪来"**。会话在两者之间来回，想法在纸面和托盘之间来回。宿主没发布工作区注册表时，所有会话都落在收件箱，和以前一样能用。

**「今天处理过的，自动进收件箱」这条逻辑本来就在**：看板按**本机午夜**切一天，`updatedAt` 在今天的会话一律上板（`★` 的不受这条限制）。只是**有工作区的会进它自己的目标，不进收件箱**——收件箱收的是"没有归属"的那部分。想让某条会话永远在板上，按 `i`（或卡片上的 `★`），或者**把侧边栏里那行会话直接拖进看板**：宿主的会话行本来就能拖（列表排序用的就是这条原生拖拽），拖到画布上时会先画出"哪块目标会接住它"的高亮，**松手即上板**——松在哪个目标上就归进哪个目标，松在空白处就跟着它的工作区走（没有工作区就进收件箱）；盖的就是 `i` 盖的那个 `★`，隔夜也在。拖进来的不是会话（比如一整个工作区行）就看板说一句「拖进来的不是一条会话」，不接。

**记住的只是位置**：每块目标落在画布哪里、**它叫什么名字**、**它要做什么（🎯）**、哪些块折起来了、哪张想法卡片写了什么、连到了谁、**哪条会话被放进了哪个目标**——这些都存在 `dsh-vim/board/v1` 的 v2 文档里，跟着这台浏览器走。0.28 及以前的"列"读进来时只保留 `★` 和"删掉"两个标记，列本身丢掉：一块地方就是新的一列，不需要再手工排。

**看板没有"保存"按钮**，也不需要：拖动松手即写入。**整理**只动想法卡片，不动目标和会话，一次给它三个去处：**已完成且连上会话的**收进顶栏的 `✓ 已完成`，卡片离开画布；**连了会话但还没做完的**贴到那个目标右侧、和那条会话齐平；**没连上的**（顺手双击写的、连接的那条会话今天不在板上的）收进收件箱右边的托盘，按写入顺序往下排、做完的沉到最后。收走几张就说一句「收好 N 张已完成的卡片」，并给一个 `撤销`——一次收走几张卡，是这一版里唯一会让画面上的东西消失的动作，得能拿回来。已经在它该在的位置上的卡不动，所以连按两次只有第一次有动作。一块目标里的会话再多，也**全部摊开在面板上**：块不再自己固定高度、不再在块内滚动，纸面在每次重画后按各面板**实际量得的高度**取尺寸，往下看就动画布（滚轮、拖白纸、`d` / `e`——指针停在面板上时，滚动的接力自然落回画布）。

**画布可以缩放**：顶栏的 `− 100% ＋` 是缩放控件，点百分比回到 100%，`Ctrl/⌘ + 滚轮` 在指针位置缩放（和设计工具一样，指针下的那一点不动）。缩放跟着这份看板的存储走，下次打开还是这个比例。

**拖动工作区时，挂在它会话上的文字卡片一起走**，连线每一帧重画，不是松手才追上来；吸附时卡片会滑过去，而不是瞬移。连线是一条很轻的曲线，交付过的卡片画虚线。

### 撤销 / 重做：删错了能拿回来

看板顶栏有两个按钮：**`撤销`** / **`重做`**。没东西可撤时它们是灰的、点不动——位置不会跳，所以第一次删东西时那一排不会突然变长。

- **只记删除**（这一版）：**想法**（`×`）、**会话**（从看板移除）、**目标**（整块关掉）。移动、改名、连线、交付都不进历史。
- **撤销就是真的复原**：想法带着它的文字、连线、已完成标记、它被收在哪（托盘/纸面）和原位置一起回来；会话只是把"别再看它"的标记拿掉；目标连同它里面的会话归属一起回来。
- **重做**再删一次；中间只要又删了别的，重做就作废（和所有编辑器一样）。
- **五十步，只在本次页面里**：刷新就清空——跨刷新还能撤的删除，是一个需要存快照的功能，这一版没做。
- **不占快捷键**：看板的键都是单个字母，加一个 `Ctrl+Z` 会是唯一一个看不见的绑定。用按钮；将来要键盘再说。
- 删目标时那条 5 秒提示仍然在，但它现在只是**历史的一个快捷入口**：它记着自己是为哪一步发的，这期间又删了别的，点它不会撤错。
### 会话卡片：进入、改名、分叉

一张卡就是一条会话。**点卡片任意处就进这条对话**——卡片是入口，不是画在画布上的一张图。整张卡就是内容：

- **内容铺满整张卡**：标题（最多两行，`改名` 藏在标题右端）、**备注**（一行输入框写，卡片上最多显示两行、字号小一档，淡色加一道细竖线）、信息行（状态小标签 → 右端 `轮数`、`✎`、`★`、`⑂`、`×`）。**信息行里不再有"多久之前"**：卡片要说的是它现在在做什么，而不是它上一次被动过是什么时候；真要看时间，侧边栏一直有。
- **⑂ 是信息行里的一个标记**，不是单独一栏：分叉仍然是从这条会话开一条新分支，只是它跟 `★`、`×` 排在一起，一个图标、`currentColor`，鼠标停上去写字。
- **点卡片 = 进入**：按下之后没移动超过 4px 就是一次点击，标题、备注、信息行、卡片空白处**都算**。
- **拖入只在拖的时候才出现**：把一张想法卡片拖到某张会话卡上时，那张卡会**浮出一层虚线落点**（`data-note-drag`），落点上写着这一下要做什么：**没完成的写「投入这个会话」**（进对话 + 黏进输入框 + 用卡片的名字命名这条会话）；**已经完成的写「收纳这个卡片」**（不再粘一遍，直接收进这条会话的已完成列表）。**不拖的时候它不存在**——既不占版面，也不在 Tab 序里，更不会有人误点到它。拖到卡片上边、不落在浮层里，仍然只是"连起来"。
- **改名是一个显式的标记，不是名字本身**：鼠标停在卡片上，标题右端浮出 `改名`；点它名字变成输入框，点名字本身则是进入。改会话名是往宿主写数据，不该和「进这个对话」共用一个动作，更不该是一次误点的结果。Enter 保存，Esc 放弃；改名走和任务窗一样的私有 retain 来源，**不会把这条对话标成已读**。按下 Enter 的那一下卡片就换成新名字——先按你写的显示，等宿主确认；宿主拒绝就把输入框和文字一起还回来，只弹一句提示不算答复。
- **同名不再是陷阱**：子会话沿用父会话的名字，而宿主只会在父名后面加 `(1)`——同一条会话分叉两次，两张子卡都叫 `X (1)`；父会话本来没名字时，子卡连 `(1)` 都没有。现在分叉落地后，看板**对着整份列表把名字定成下一个空号**（`X (2)`），并弹一句「已分叉：X (2)」告诉你它叫什么。`⑂` 在这次分叉回来之前**不再响应**（连点两下只出一条分支），卡片上写着「正在分叉…」。
- **仍然重名的卡会自己报号**：不管名字是怎么撞上的（早年分的叉、手工改成同名、同一个工作区里两条还没起名的会话），只要两张卡在板上同名，信息行后面就多一个 `#1/2`、`#2/2`——按会话 id 排序，所以**永远不跳号**；名字不撞就不显示。
- **进行中 = 一圈会呼吸的光**：这条会话正在跑时，卡片是一圈很淡的环，**2.8 秒一次呼吸**（只有环的透明度在动，字和边框都不动），左边一道 2px 竖条，状态标签前一颗 5px 的点**1.4 秒一跳**——呼吸和心跳是 2:1，读起来是一套节奏。它不再是“会走的虚线框”：跑马灯是选框的语言，而这个状态一跑就是几分钟，高频循环只会变成噪音。**等你（批准/回答）不呼吸**：那是你没在动，不是它在动，所以换成一圈静止的琥珀色。
- **刚刚完成 = 一次脉冲**：跑完还没看过的那一条，卡片**第一次被画出来时**边框亮一下再收回去——760ms，快起慢收，和 F 弹窗开窗时标签的那一拍是同一条曲线。**一次就是一次**：拖一下卡、点个星、状态一变引起的重画都不会重播；播完留一圈很淡的环，点开看完就消失。
- **`✎`**：给这条对话钉一句话；**`★`**：收藏（过夜也不掉）；**`×`**：从看板上删掉，不是归档，之后再用到会自己回来。轮数是逐条读投影，读不到就不显示角标，不编数字。
- **拖动整张卡，换一个目标**：按住卡片（标题、空白处都行，卡片里没有别的可拖）拖到**任意一块目标**上松手，它就被记进那块目标，那块目标在拖动过程中会亮起来告诉你松手会落在哪。**松在空白画布上就给它单开一块目标**：名字是「来源目标名 + 序号」（`dsh-vim 2`），卡片直接放进去，双击标题可以改成你真正想叫的名字。拖过 4px 才算拖，没拖动的一下就是一次点击（点卡片进对话、点 `✎` 写想法、点 `改名` 改名字）。
- **最后一条会话不能拖上纸面**：目标里只剩一张卡时，把这张卡拖到空白处会被**滑回原处**，卡片下面浮一行说明。理由很实在——拖上纸面本来就会新开一块目标：旧目标空了、新目标只有这一张，同一种摆法多出一块板。要让它独立，就**拖到另一块目标里**；想先立个地方，用 `＋ 目标`。
- **🎯 写在这一块上，不写到会话里**：它是看板自己的记录，改会话、点进去、分叉都不会动它，也不会同步给宿主。
- **重叠时，最后按的那张在最上面**：卡片被按下的瞬间抬到最前，看板重画时也记得是哪一张，所以叠在一起的那摞永远是你正在看的那张在最上面。

**分叉线**：一块工作区里，父卡下面缩进一层挂它的分支，左侧一条竖线 + 一小段横线接到子卡——像 git 图那样从上往下读。父会话不在今天的看板上时，子卡落回根位置，并用一行淡字写**"分叉自「名字」"**（点它进父会话），不画一条通向没有的线。

**分支落在父卡那一块**：分叉完，子卡会直接记进父卡所在的目标——你把它拖进过自建目标的，就跟着进那个目标——所以线永远有两头可连。父卡落在画布当前视野之外时，看板会把画布滚过去，让新子卡进视野。这条记录只写一次：之后你把它拖到别处，就以你拖的为准。

**必须说清的一条**：DeepSeek Harness 的普通分叉**不写父会话 id**（源码里就是"the fork has no durable source relationship"），所以**历史分叉无法可靠还原**。本插件从加载那一刻起监听 `sessions.fork`，凡是在这台机器上经过界面的分叉（侧边栏、快捷键、看板上的 `分叉`）都会记下父子；在那之前就存在的分支，看板诚实地当作独立会话显示，不猜。`board().lineage` 能看到记下了哪些。

**看板和 F 弹窗、W 弹窗互斥**：一个开着的时候，另一个打不开（这些窗口开着时按键归窗内）。所以 `j` 和 `f` 不能绑同一个字母——设置页会拒绝，改成别的字母就好；老配置里如果两个撞了，看板这个较新的座位会自动让开。

**键盘只有两条**，因为它本来就是个鼠标窗口：`Esc`（拖动中只取消这次拖动；悬浮窗形态下关窗）、再按一次 `j` 回到对话。**鼠标指在哪块上，`d` / `e` 就滚哪块**。点看板外面同样关（悬浮窗形态），那一次点击照常作用在页面上。

### 文字卡片：想到什么，先放在画布上

画布上可以随便写**文字卡片**（和"钉在某个对话上的想法"是两回事：那种跟着会话走，这种是自由摆放的便签）。

- **怎么来**：顶栏 `＋ 卡片`，或者在画布空白处**双击**——就在你点的地方长出来，光标已经在里面。Enter 换行，点别处保存（每敲一个字都写盘，刷新不会丢），Esc 放弃。
- **第一行是标题**：卡头那行从左到右是 `☐` · **标题** · 它的目标色点 · `×`。你直接打的第一行就是它——不用另开一个标题框；第一行空着时那里写「聚焦一个主题」。新建时字段已经打开、**光标就在第一行**，框里更淡地写着同一句 **「聚焦一个主题」**——一句话，一个地方说，不解释字段，只说该做什么。
- **收起 = 标题 + 2 行正文**：正文只显示两行，超出的最后一行**淡出**（卡片带 `data-clipped`），不滚动。要读全文就点它——**点一下整张卡展开到全部文字，同时字段打开**（光标在末尾，直接就能改）。Esc / 点别处收起，**展开不写盘**：下次打开还是两行。
- **纸是不透明的**：两张卡叠在一起时，**上面那张完全挡住下面那张**——看板上的纸不是玻璃，能互相看穿的纸就没法当纸用。

- **一把尺子**：卡片的尺寸先由 `boardNoteMetrics` 算出（行高 23px、字 14px，随看板字号等比缩放），**文字和输入框都用这一把尺子**，所以“计划多大”和“画出来多大”是同一件事——一列卡片能对齐、点开也不跳，是因为两处算的是同一个数。
- **点 = 看全文 + 改，拖 = 搬位置**：按下没动过 4px 就是一次点击，展开并打开字段；拖过 4px 只是移动卡片。**一句话都没写的卡片不留下**：空着关掉，纸自己消失。
- **叠在一起时，正在用的那张在上**：每一张卡都有自己的层号（按绘制顺序），被按到 / 被打开的那张永远压在上面，所以摞起来的便签不会互相遮挡你看的那张。右下角**没有拉手了**：高度由内容决定，不再需要手拖。
- **卡头只有三样**：左边 17px 的方框是**已完成**；一颗**颜色小点**说明它交给了谁——**颜色的那个目标**，名字在悬停提示里；然后是 `×`（删掉）和**链条断开那个图标**（解除连接），这两个是次要动作，鼠标停上去、或刚按过这张卡时才出现。
- **已完成的想法在这条会话旁边看**：一张卡收到过已完成、又连在它身上的想法时，信息行里会多一个 **`▤ 数字`**——点它，**就在这张卡右侧**弹出一个小面板（便签的纸、卡片那么宽、头部只有 `已完成 · 数字` 和关闭）。面板里是**一张张卡片**，和收件箱里那些一样：**一行标题**，点一下整行展开全文，再点收起；每行右侧常驻 `↓`（取回纸面）和 `×`（删掉）。数字是这条会话的；没有就一个也不显示，删空了面板自己关。
- **颜色跟着目标走，不跟着名字走**：目标是十二个色位轮着用的，同一个起点往后错开，所以**改目标的名字不会换颜色**、两个目标也不会撞成相近色；**连到某个目标的笔记，整张纸用那个目标的颜色**（纸、左边的竖条、那颗小点都是）。没连线的笔记、以及收件箱里的，统一是琥珀色——那是"没人认领"的颜色。

- **已完成 = 纸和字一起变**：纸从琥珀变成中性色，文字划掉并压暗，**卡片仍然读得清**（以前整张卡半透明加去色，等于看不清自己写了什么）。它和“把卡片拖到会话上交付”落的是同一个状态，区别只是这一次是你自己按的。
- **怎么放**：按住卡片**任意处**拖，随便摆。摆在工作目标旁边、压在块上、离得很远都行。**卡片叠在一起时，最后按的那张在最上面**（按一下就抬到最前，看板重画也记得）。
- **怎么删**：`×`（鼠标停上去才出现），删掉就是删掉。
- **连到一条会话**：把卡片拖到一张**会话卡片**上（不是按钮上）松手——卡片会**吸附到这块工作区的右侧、和那条会话齐平**，并画一条线连到它，卡头写着"已连到「名字」"。这只是"这句话属于这件工作"，**不会进对话、不会发送**。点卡头上的 `断开` 可以断掉这条线。**整理**把它摆到同一条轨道上，所以按一次就回到那条会话旁边。
- **交给一条会话**：拖着一张想法卡时，会话卡片上会浮出一个**虚线落点**（不拖就不存在）；把卡松在它上面——**直接进入这条会话，并把卡片里的字粘贴进输入框**（作为一次粘贴放进草稿，不替换你已经写的字；**不会自动发送**，发不发由你按），**同时这条会话改用卡片的名字**：卡片第一行就是标题，交付的这一下就是命名的这一下，落地后弹一句「已命名为：标题」。改名走和任务窗一样的私有 retain 来源，**不会把这条对话标成已读**；宿主拒绝时名字保持原样，只弹拒绝的原因。只在「投入」这一下命名：**连线不命名**（拖到卡片身上只是"这句话属于这件工作"），**收纳不命名**（已完成的卡进列表），**没找到输入框也不命名**（那次交付没有发生）。原文字卡片**留在看板上**，吸附在那条会话旁边，**置灰、标"已完成"**，线也变成虚线——它是这次交付的痕迹，不是垃圾。输入框没找到时卡片不动，并提示一句。
- 卡片里的字**不会跟着账号走**，只在 `dsh-vim/board/v1` 里。想长期留的东西，还是抄进对话或文件。

### 已完成：收起来的那些

收纳处有两个入口，打开的是同一列：

- **在会话卡片上**：那条会话收着东西时，卡片信息行多一个**归档图标 + 数字**；点它只列出**交给这条会话的**那一部分。没有收着东西就不画——门不立在空房间前。
- **在顶栏**：`✓ 已完成` 是"全部的"，还收着几张就写几个数字；**空着的时候它整颗不出现**，不占位置。一个都找不到会话主人的卡（那条会话今天不在板上）只能从这里看。

每行是**一句话 + `→ 交给了谁`**，行末那半句是它值得留着的全部理由。两个入口都同时是按钮，所以收进去的东西永远隔一次点击就能看见，不会变成“消失了但还在某处”。

- **只收“做完 + 连上”**：两样缺一样就不收。做完了但没连线的留在收件箱（那是“没人认领”，不是“已完成”）；连上了但没做完的照旧贴在会话旁边。
- **能拿出来**：在列表里把一行**拖出来**，它就回到纸面（收件箱那一栏是同一套手势）。
- **自己会走**：在列表里取消勾选，或者断开那条线，这张卡**立刻回到纸面**——一个叫“已完成”的箱子不该装着没做完的东西。它回到原来的位置，下次整理再决定它去哪。
- **交付的痕迹**：把想法卡拖到会话的投放区松手（交付）之后，卡片就是“已完成 + 已连上”，所以下一次整理它会进这里，画面上不再留那张灰色的卡。交付本身不变，只是痕迹从画布挪进了这个列表。

### 想法：写在卡片上

正在一个对话里干活，忽然想到一个点子——**这个点子记在这个对话的那张卡上**，别急着开新会话。

- 卡片的信息行末尾有一个淡色的 `✎`：点它，**卡片里当场长出一个输入框**，写一句话，回车记下。`Esc` 放弃，**点别处也算记下**（那一次点击照常作用在页面上）。
- 记下之后那一行就显示在卡片标题下面（淡色、左边一道细竖线），跟着卡片被移进别的工作区、被折叠、被删掉，因为它本来就长在那个对话上。**再点这一行就是改**：框里带着原来那句并全选，直接打字替换；**清空回车就是删掉**。
- 键盘也能到：在任意对话里按 `n`，看板打开、光标直接落在**当前对话那张卡**的想法框里。这就是"想到什么马上记下来"的最短路径。
- **没有打开任何对话时，`n` 不猜**：它提示你先打开一个，而不是把想法记到一个你不知道的地方。
- 正在写的时候，**板子的自动刷新会停下来**（等状态、轮数、时间都不会把你正在写的那个框换掉）；回车或离开之后恢复。
- 想法存在 `dsh-vim/notes/v1`，**和看板的排列分开存**：工作区摆乱、看板读坏，都带不走你写过的话。

**为什么挂在对话上，和自由摆放的文字卡片分开**：一句话的价值一半在内容、一半在它冒出来的上下文。挂在对话上，三天后你看到"这个交互应该反着来"时，还知道说的是哪个交互；孤零零一条便签，三天后就是垃圾。自由摆放的**文字卡片**是另一件事：它是画布上的草稿，可以拖到会话旁边连上线，也可以按 `进入` 交给一条对话。

### 历史：一天一页

看板是一天的视图：它画的是"今天动过的"会话。**过了午夜，昨天那些成员就不在投影里了**——所以历史不是"以后再把它们算出来"，而是当场封存。

- 看板每画一次，就把**这一刻的页面**写进 `dsh-vim/history/moment/v1`（内容没变就不写）。日期翻过去之后，下一眼看板打开时，这份页面按**它自己的日期**存成一天一页；第二天没开过就没有那一天，不凭空造。
- 一页里存的是**封版的东西**：每个目标（名字、🎯、位置、折叠）、每条会话（标题、当时的状态词）、想法卡片和当时的想法文字。标题和状态是那一刻的字面值——**id 只是顺带留的指针**，点得开就跳过去，跳不开就只显示文字。
- 页面存在**看板自己的数据库**里（IndexedDB `dsh-vim-history`，一天一条记录），不是 localStorage：历史只在你打开面板时读，不需要同步 API，也不该跟看板抢那 5 MB。看板自己的排列仍然在 localStorage——重画必须同步读它。
- 看板标题上的 `历史` 打开一个只读面板：日子列表 → 点开一天看目标、会话、卡片 → 底下一个 `恢复为今天的起点`（**按两下**才动手）。恢复是**复制**：先把当前的样子存进「恢复前」（一个槽位，跨刷新还在），再把那一天的五张表写回今天；**快照本身全程只读**，一个字节不改。
- **承**：一天翻过去时，上一页里的会话会被带进今天，条件是它**没完成、没从板上删掉、没归档**。卡片信息行末尾写 `承 N 天`。它**不会自己消失**：要么它又动了一次（变回普通行），要么你把它从板上删掉或归档，要么你在历史面板里按 `放下 7 天没动的`。这是"睡一觉东西不会自己没"。
- `导出` 把看板、想法和全部历史写成一个 JSON；`导入` 读回来，先存「恢复前」再写。保留天数在设置页（默认 3650 天），超了从最旧的删；数据库满了会先删最旧的一天再重试一次。
- **写不进去会说话**：localStorage 满的时候不再静默——弹一句"看板没能保存：存储已满"，并且**这份改动留在内存里继续显示**，每次重画、每 5 秒都重试一次，腾出空间就写进去。以前这里只 `console.warn`，配额一满就是"你以为存了、其实没有"。

### 推理等级

按 `q` 把**当前对话**的推理等级换下一档，到头回绕。**模型不动**——它只改推理强度，和 composer 那个模型菜单里的「推理」行做的是同一件事，所以两边看到的是同一个选择。

- **档位跟着模型走**：顺序就是宿主自己那个菜单的顺序。模型声明了默认档时，是它公布的那几档；没声明时前面多一项「提供方默认」。适配器没公布等级时，`q` 告诉你一句，什么都不会发生。
- **每按一下都有回话**：输入框上方浮出一条 1.6 秒的提示，写着换到哪一档、第几档，比如 `推理等级 高  3/3`。失败理由也写在同一条上，不会按了没反应。
- 提示贴着输入框上沿，输入框自己挪了它也跟着挪。宿主万一没有富文本输入框，提示退回窗口顶部。
- **按住不算连按**：系统连发被吞掉，必须一下一下按。
- **正在跑的任务不受影响**：完整选择从下一轮请求开始生效。
- **输入框里它就是个普通字母**。**任务窗开着也能按**——它是页面的键，不是任务窗的键。

为什么用循环而不是弹窗：档位通常只有 3–5 个，开窗、选行、关窗比按两三下慢。

### 模型选择窗

按 `w` 弹出一个小窗，每一行是一个模型。**选中的那一行**把它的全部推理档位列出来，高亮的那一档就是会提交的档位；其余行只标出会落在哪一档。

**先在设置页勾一遍**：设置 → Vim 滚动 → **快捷键 → 常用模型**，清单从宿主自己的模型目录里读，勾哪几个、`↑` `↓` 怎么排，弹出的窗里就怎么列。

```
┌ 切换模型 ─────────────────────────────── 3 个 ┐
│ DeepSeek Chat       无档位       deepseek     │
│▸当前 DeepSeek Reasoner  低 [中] 高  deepseek   │
│ Space Bunny Free    无档位       bunny        │
├────────────────────────────────────────────────┤
│ w 确定 · d/e 选择 · Tab 档位 · Esc 取消         │
└────────────────────────────────────────────────┘
▸ = 键盘选中的行    [中] = 这一行会提交的档位
```

`当前` 标签是模型名前面的一枚紫色徽标，不是单独一列——低频操作里，为对齐留一整列空格不值。未选中的行只标档位名（紫色），不铺开全部档位：**决定只发生在选中行上**，其他行的完整档位表正是把每行撑成两行的原因。

一次完整的操作：

1. `w` 开窗
2. `d` / `e` 上下选模型（`↑` `↓` 也行）
3. 想改档位就按 `Tab`（`Shift+Tab` 反向，`←` `→` 同义，`q` 也行）；不改就跳过
4. 想调顺序就按 `Shift`+`d` / `Shift`+`e`（`Shift`+`↓` / `Shift`+`↑` 同义），**顺序会记住**
5. `w` 确定，切过去并关窗

- **开窗时选中「当前」那一行**，所以进去第一眼就知道自己在哪。那一行名字前面挂一个紫色的 `当前` 徽标——这是循环做不到的：循环要按一下才知道自己走到哪，这个窗在你按任何键之前就说了。
- **选中行列全档位、当前档高亮**，其余行只标会落在哪一档。停在某一行的档位名，就是切过去会得到的档位。
- **只选模型不碰档位时，档位跟着走**：新模型也公布当前那一档就带过去；否则不提交等级，由宿主落到那个模型自己的默认档。行上标的/高亮的就是这个结果——**看到哪一档，切过去就是哪一档**。
- **按了 `Tab` 就是明确指定这一档**，确定时原样提交。
- **`q` 在模型窗里 = 换档位**，和 `Tab` 同一个动作。窗正在画这一栏，让它在背后偷偷改档位会让高亮对不上，所以它被窗接走、而不是静默吞掉。窗关着时 `q` 照旧是页面的推理等级键。
- **可以在窗里调顺序，`Shift` + 上下键把选中的那一行挪一位**。顺序写进同一份「常用模型」清单，所以设置页里看到的、之后重开的，都是这个顺序，重载也在。**只挪顺序，选中项跟着那个模型走**（按两下不会跳到没看的地方）；**不提交任何东西**，调顺序不等于换模型。
- **目录里暂时不可用的模型不会因为调顺序被删掉**。它不在窗里，但保留在清单里的原位——挪一行是你看得到的操作，不该顺手改掉看不见的那部分。
- **不鼠标碰也能点**：点某一行 = 选中并确定；**点某个档位 = 切到这个模型 + 这个档位**，一步到位。
- **`Esc` 取消**。**点窗口外面的任何地方也是取消**，和 `Esc` 完全一样：**取消不提交任何东西**——开窗只是读一遍目录，来回翻几下再点外面，宿主那边什么都没发生。
- **窗开着时键盘归它**：`w`、`d`、`e`、`↑` `↓`、`Tab`、`←` `→`、`q`、`Enter`、`Esc` 都是窗的键，别的字母被吞掉，不会漏到页面上。
- **`Enter` 是确定的常驻别名**，和任务窗一样。
- **确认失败时窗不关**，宿主的拒绝理由写在窗底栏，选中的那行还在，可以直接改选或再试一次。成功才关窗，回一条 1.6 秒的提示，写着切到了哪个模型和哪一档（`模型 DeepSeek Reasoner · 高`）。
- **正在提交时窗是冻的**：切完之前再按 `w` 不会提交第二次。
- **当前模型不在清单里**（会话的默认模型、或一个你后来删掉的）时，选中落在第一行，而不是没有选中。
- **目录里已经不提供的模型不会出现在窗里**。所以一个提供方登出了，窗里就少几行，清单本身不会被改掉。
- **没公布档位的模型显示灰字「无档位」**，按 `Tab` 会在窗底栏说明一句，什么都不会发生。
- **换行会丢掉手动改过的档位**：档位标记只属于你正停在的那一行，移到别的行再移回来，它回到「跟着走」的规则。一次选择、一次确定，不做逐行记忆。
- **档位栏挤不下时裁自己**：名字很长、或某个模型档位特别多时，裁掉的是档位而不是提供方——提供方也是这一行的事实。正常情况下都不触发。
- 其余和 `q` 一样：**输入框里它是普通字母**、**任务窗开着也能按**（会在任务窗上面开）、**正在跑的任务不受影响**、**按住不算连按**。

**清单为空**、或**清单里的模型当前都不可用**时，`w` 只提示一句，**不开一个空窗**——一个没有可选项的窗除了让你按 Esc 之外没有别的用处。

**要知道的一件事**：换模型会在**下一条请求**之前，往对话里插一条宿主自己的提示——`[model changed: …]`，告诉你上面几轮是哪个模型写的。这是宿主行为，插件改不了；切换还会减少提供方侧的缓存复用。

### Enter 做什么

设置页有一项 **「Enter 做什么」**，四档：

| 档位 | 裸 Enter | 换行 | 发送 |
|---|---|---|---|
| **发送**（默认） | 发送 | `Shift+Enter` | `Enter` · `Ctrl/⌘+Enter` |
| **换行** | 插入换行 | `Enter` · `Shift+Enter` | `Ctrl/⌘+Enter` |
| **什么都不做** | 什么都不做 | `Shift+Enter` | `Ctrl/⌘+Enter` |
| **连按两下 Enter 发送** | 插入换行 | `Enter` · `Shift+Enter` | **连按两下 `Enter`**（250ms 内） · `Ctrl/⌘+Enter` |

**默认不改宿主行为**：让每个对话换一种发送方式，不该由一个滚动插件在装上时替你决定。要改自己去设置页切一下，即时生效。

- **`Ctrl/⌘+Enter` 是宿主自己的发送快捷键，不是插件加的**——所以后三档没有另造一个发送键。Mac 上提示写 `Cmd`、其他平台写 `Ctrl`。
- **「连按两下 Enter 发送」是为记不住快捷键的人准备的**：它和任务窗的 `f` 两下、模型窗的 `w` 两下是同一种手势——同一个键按两下就是确认。第一下 Enter **照常立刻换行，不延迟**；250ms 内再按一下才发送。中间打了别的字、或者间隔超过 250ms，就当成两个段落，第二下仍然是换行。**想连打两下空一行的话，改用 `Shift+Enter`**——它在任何档位下都只换行、不发送。
- **选「换行」/「什么都不做」/「连按两下 Enter 发送」时，输入框下方那一行常驻一句淡灰提示**，写明现在按什么发送，比如 `Enter 换行 · 连按两下 Enter 发送 · Ctrl+Enter 发送`。它挂在宿主给输入框预留的那一行里（`conversation.composer.dock`，上下文用量表旁边），水平居中，跟输入框一起长高；切回「发送」立刻消失。
  - 这一行是**通过宿主自己的 slot 注册进去的 React 组件**，不是插件往页面上贴的元素。所以位置、居中、跟随布局全部由宿主负责，插件不用量、也不用跟着草稿高度重算。
  - 提示**不画背景、不画边框**，借宿主自己的弱化文字颜色，明暗主题下都读得清；`pointer-events: none`，不挡点击、不吃按键。
  - 只在**消息输入框里**生效。终端、任务窗的重命名框、计划编辑器、设置页的字段——Enter 一律照旧。
- **斜杠菜单、`@` 引用这类候选列表开着时，Enter 永远归它**：那是"选中高亮项"，插件不插手。所以打 `/plan` 再按 Enter 仍然是执行命令，而不是换行。
- **输入法合成中的 Enter 不碰**：候选词上屏那一下照常走输入法。
- **实现上不插字符**：拦截掉的那一下，是把宿主自己的 `Shift+Enter` 换行手势（`client.js` 的 `breakLine`）递回输入框。所以换行拿到的是和手按 `Shift+Enter` 完全一样的软换行，不是新段落。
- **双 Enter 档的发送走的是宿主自己的键**：第二下不是插件自己去点发送按钮，而是把宿主自己的 `Ctrl/⌘+Enter`（`client.js` 的 `sendFromComposer`）递给输入框。走的是宿主真实的发送路径，草稿一个字都不动。**这个改写出来的键会被打上标记**（`REWRITTEN_FLAG`）——它会冒泡回插件自己的监听器，不打标记的话插件会把它当成"用户又按了一次键"，配对当场失效（0.15.1 修的就是这个）。
- **按住 Enter 不会发送**：只有"抬起再按下"才算第二下，键盘自动连发不算。这是双 Enter 档最重要的一条安全线。
- **四档都只管这个插件管的输入框**：其他窗口、其他应用、其他输入框不受影响。

### 手感

滚动不是"按一次瞬移一段"，而是 rAF 驱动的缓动：每次按键把目标位置推进 `step` 像素，实际位置按 `1 - exp(-dt/tau)` 逐帧逼近，因此帧率无关、且不会越过目标。

按住时**不依赖操作系统的键盘重复**（那个有 ~500ms 首延迟且节奏不匀），改为自己接管连发并逐步加速（65 ms → 45 ms）。

## 设置页面

设置 → **Vim 滚动**。改动**即时生效**，不需要重启。

**快捷键**：见上面的「键位与功能绑定」。

**常用模型**：从宿主自己的模型目录里勾，勾哪几个、什么顺序，`w` 弹出的窗里就怎么列。读不出来或宿主没发布目录时，这一组会写明为什么，而不是空着一片。

**模型窗：换档位**（`modelLevelKey`，默认 `Tab`）：模型窗里换推理档位的键，`Shift` + 它反向。只在模型窗里有效。

**焦点**：Esc 离开输入框；空格离开空输入框；不自动聚焦输入框；发完消息交还键盘；**Enter 做什么**（发送 / 换行 / 什么都不做 / 连按两下发送，见下）。

**弹窗外观**：字体大小 11–20 px；弹窗宽度 480–1400 px（再宽也会被 `94vw` 兜住）；弹窗高度 40–95 vh（用 vh 所以换屏幕跟着走）；行距 3–14 px；弹出位置顶部 / 居中 / 底部。

**速度与手感**：滚动步长 40–600 px；缓动时长 10–250 ms（越大越绵软，越小越跟手）；连发延迟 80–800 ms。

**焦点**：四个开关，见上。

**顶/底留白会自己让路**：把高度拉到 95vh 时，14vh 的上/下边距会缩到 3vh，保证整块还在屏幕里。让掉的是边距，不是你要的高度。

配置存在浏览器 localStorage 的 `dsh-vim/settings/v1` 下，跟着这台设备走，升级插件不会被清掉。

## 安装

`desktop` profile 由 Electron 应用独占，CLI 会被拒绝。走应用内的插件管理器：

1. 侧边栏 → **插件** 页
2. **安装组合包**，spec 填本仓库的绝对路径
3. 若未立即生效，重启 DSH Desktop

其他 profile（如 `web`）可以直接用 CLI：

```sh
dsh plugin --profile web add "G:\桌面\dsh-vim"
```

本包没有任何依赖、没有 install/build 脚本，因此**不需要** pnpm 的 `allowBuilds` 授权。

## 实现

插件**没有 DOM 抓取**，用的是宿主已有的客户端服务：

| 用途 | 服务 |
|---|---|
| 会话列表 | `ctx.sessions.list.getSnapshot()` |
| 状态 | `ctx.get('uiSession').sessionStatus` |
| 轮数 | `ctx.sessions.retainScope(id, 'dsh-vim')` → `projections.faceOf('sessionStats')` |
| 文件夹 / 归档 | `ctx.workspaces.list.getSnapshot()` 的 `items[].sessionIds` 和 `archivedSessionIds` |
| 切换 | `ctx.get('uiWorkspace').openSession(id)` |
| 重命名 | `ctx.sessions.using(id, { source: 'dsh-vim' }, ref => ref.binding.session.rename(title))` |
| 归档 | `ctx.uiWorkspace.archiveSession(id, {})` — **不带** `stopActivity`，见上文「归档」 |
| 推理等级 | `directory.store.getSnapshot()` / `directory.select({...})` |
| 常用模型（弹窗列表 / 切换） | `directory.load()` 的 `groups` → `directory.select({provider, model, reasoningEffort})` |
| 常用模型（设置页列表） | `ctx.modelDirectories.catalog.load()`，不需要打开任何会话 |

过滤规则和状态优先级都照宿主自己的 `sessionVisible` / `sessionStatuses` 抄的，所以任务窗里能看到的、标出来的，就是侧边栏里能看到的。

这些服务是**懒探测**的，没有写进 `inject`。缺哪个服务就只少对应的那部分，其余照常工作：

- 没有 `sessions` / `uiWorkspace` → 丢的只是任务窗，**滚动照常工作**，`f` 什么都不做也不吞键。
- 没有 `workspaces` → 任务窗照常工作，只是不做归档过滤、行上也没有文件夹。
- 没有 `uiSession` → 状态退化成目录里的 `running` 布尔值。
- 没有 `retainScope` → 没有轮数，别的什么都不少。
- 没有 `using` → `r` 会告诉你这个宿主不支持重命名。
- 没有 `uiWorkspace.archiveSession` → `g` 会告诉你这个宿主不支持归档。
- 没有 `modelDirectories` → `q` 和 `w` 各提示一句，滚动和任务窗都不受影响。

**一个必须避开的坑**：retain 的来源绝对不能用 `mainView`。`uiSession.reconcileStatus()` 里有 `if (isMain(id)) this.completionUnread.delete(id)`，一旦某个会话被当作主视图挂起，它的「刚刚完成」标记就被清掉了。所以插件用的是 `'dsh-vim'` 这个私有来源。轮数和重命名两处都守这条，测试里有专门的用例。

## 调试

DevTools 控制台（`Ctrl+Shift+I`）：

```js
window.__dshVim.settings()                       // 读当前配置
window.__dshVim.update({ downKey: 'j' })         // 改配置，和设置页等价，会持久化
window.__dshVim.reset()                          // 恢复默认

window.__dshVim.palette(true)                    // 直接弹开任务窗（不等按键）
window.__dshVim.board()                          // 看板状态：open / mode / blocks（目标块：key、label、kind、folded、ids）/ goals（改过名的目标：块 id → 名字）/ intents（目标 → 写下的那句 🎯）/ front（最后按下的那张卡）/ inbox（未归工作区的会话）/ cards（画面上画出的会话）/ loose（想法卡片：text、link、done、位置）/ lineage（看到的分叉：子 → 父）/ places / starred
window.__dshVim.board(true)                      // 直接弹开看板（悬浮窗形态；侧边栏页走 `j` 或侧边栏入口）

window.__dshVim.note('会话 id')                  // 这条对话上写的想法；editing 是正在写的那个会话 id（空 = 没有框开着）
window.__dshVim.phase()                          // 全部阶段标注 { 会话 id: 阶段 }
window.__dshVim.phase('会话 id')                  // 读一条（未标注返回 ''）
window.__dshVim.phase('会话 id', 'code')          // 标成编码
window.__dshVim.phase('会话 id', null, true)      // 按一次循环推进
window.__dshVim.clearPhases()                     // 清掉全部标注
window.__dshVim.probe()                          // 当前会被滚动的元素 + 记下的鼠标位置 + 输入框状态
window.__dshVim.models()                         // 常用模型清单 + 目录提供了什么 + 按得到哪几个（Promise）
window.__dshVim.modelPick()                      // 模型窗状态：open / index / total / level / marked / levelSet / rows（每行带 levels 和 marked）
window.__dshVim.modelPick(true)                  // 直接弹开模型窗（不等按键）
window.__dshVim.history()                        // 历史里的日子（Promise，最旧在前）

window.__dshVim.historyPanel(true)               // 直接打开历史面板

window.__dshVim.stop()                           // 立刻停住动画与连发，关掉两个窗
```

常见问题：

- **按键没反应** → `probe()` 返回 `element: null` 说明那个点上没有可滚容器。返回了侧边栏而不是正文，**那正是鼠标指着的地方**，把鼠标移回正文即可。`pointer.seen === false` 表示插件还没见过鼠标（纯键盘操作），此时走焦点/中间那条兜底路径。
- **设置页没出现但滚动正常** → 看控制台里有没有 `[dsh-vim] settings section registration failed`。滚动本身不受影响。
- **任务窗按了没反应** → `palette()` 看 `available` 是不是 `false`。是的话说明这个宿主没有发布 `sessions` / `uiWorkspace`。
- **归档的对话还在列表里** → 这个宿主没发布 `workspaces` 注册表，此时任务窗不做归档过滤。
- **按 `g` 说「先停下来再归档」** → 那条对话正在跑任务。宿主会拒绝归档有工作在跑的会话，而插件不会替你停它——停掉之后（或等它跑完）再按一次 `g`。
- **`w` 说「还没配置常用模型」** → 设置页那一组还没勾。去设置 → Vim 滚动 → 快捷键 → 常用模型。
- **`w` 什么都没弹** → `models()` 看 `entries` 是不是空的。空而 `favorites` 不空，说明清单里的模型当前都不在目录里（多半是提供方登出了），这种情况只提示一句，不开空窗。`modelPick()` 的 `open` 是 `false` 也说明窗没开起来。
- **模型窗里选了但没切过去** → `modelPick().notice` 里是宿主给的理由。

## 结构

```
dsh-vim/
├── package.json        dsh.bundle.patch + dsh.client
├── cordis.patch.yml    insert 一行 dsh-vim，让 Loader 挂载本插件
├── dsh.plugin.json     插件管理器展示用的清单
├── lib/
│   ├── index.js        Host 面：空壳 apply，只为让这一行能挂上
│   └── client.js       浏览器面：全部逻辑
└── tools/
    ├── selftest.mjs    假 DOM + 虚拟时钟驱动真实 client.js 的行为断言
    └── probe.patch.yml 不落盘的合成验证 overlay
```

没有构建步骤：`lib/` 是手写的、可直接运行的 JS。设置页用 `react` 的 `createElement` 手写，不引入 JSX 或 UI 组件库；任务窗是纯 DOM + 内联样式，零依赖，并且能被假 DOM 直接断言。

## 已知限制

- **「Enter 做什么」默认是「发送」，也就是不改宿主行为**。只有你主动切到「换行」/「什么都不做」/「连按两下 Enter 发送」，裸 Enter 才不再发送，且此时输入框下方会常驻一句淡灰提示写明发送键。
- **提示挂在宿主给输入框预留的那一行里**（`conversation.composer.dock` slot）。宿主换了名字、或者干脆没有这一行，提示就没了——但插件的其他部分照常工作，Enter 换行照旧生效，只是不再提醒你按哪个键发送。
- **「什么都不做」这一档下，`Enter` 在输入框里彻底不做事**——不发送也不换行。输入框里能换行的只有 `Shift+Enter`。
- **双 Enter 档占用了"连按两下 Enter = 空一行"这个手势**：想空行得换条路走。两条都行：**连按两下 `Shift+Enter`**（最快，完全不用掐时间），或者**两下裸 Enter 之间停超过 250ms**。这是这一档唯一真实的手感代价。
- **双 Enter 档的误发是不可逆的**。`Ctrl/⌘+Enter` 猜错的代价是"没发出去"，双 Enter 猜错的代价是"发出去了"。250ms 是取"够快能顺手按两下、够慢不至于把空行按成发送"，但它不是万能的——这也是它出厂不默认、并且四档里排最后的原因。
- **双 Enter 的第一下会往草稿尾部留一个换行**。宿主发送时会 trim 掉，所以正常看不到；万一某个版本不 trim，消息尾部会多一个空行。插件不主动删它——那意味着去改用户的草稿，代价比一个空行大得多。
- **焦点落在 iframe 内**（侧边栏浏览器、HTML 预览）时收不到按键，按键事件不会冒泡到父窗口。指针停在 iframe 上时命中测试只能拿到 iframe 这个元素本身，于是往上落到承载它的窗格。**「点窗口外面关窗」在 iframe 里同样收不到**：按在 iframe 内部关不掉任务窗或模型窗，得按 `Esc`。
- **「不自动聚焦输入框」只认富文本输入框**。普通 `input` / `textarea` 一律不管。换个把输入框做成 `textarea` 的宿主，这条规则会失效（滚动本身不受影响）。
- **空格进输入框靠 `COMPOSER_SELECTOR`**（`[data-lexical-editor="true"]`，Lexical 自己打的标记）或**已经见过一次的那个元素**。宿主换了编辑器又没打标记时，页面刚打开、输入框还没被聚焦过的那一小段时间里空格可能没反应；先点一下输入框就记住了。
- **「空输入框」的判据是编辑器根元素的文字为空**，所以附件不计入：只放了附件、一个字没打时，空格仍然会离开输入框。
- **计时只从"插件看到的那次开始"算**。起点超过 12 小时就不认，等下一轮开始时恢复。
- **任务窗第一版只有列表**，没有搜索框。列表超过 20 条的旧对话要展开 `更多` 才翻得到（键盘可以走到 `更多` 上）。
- **想法只存在这台设备的 localStorage 里**（`dsh-vim/notes/v1`），不在会话本身、不跟着账号走。清掉站点数据、换浏览器、换 profile、换端口（origin 变了），写过的话都看不到。它是草稿纸，不是笔记库——真正要长期留的东西应该写进对话或文件里。
- **一个对话只能挂一句话**，框是单行的。想记两条就分两行写在不同对话上，或者把它抄进对话；插件不提供"转成会话"的按钮。
- **看板页需要宿主的侧边栏页座位**（`main` + `sidebar.panellist` 两个槽）。没有它们的宿主上，`j` 退回悬浮窗，想法仍然能写，只是不能当常驻页开着。页面的配色读宿主主题变量，宿主改了变量名只会掉色，不会让看板画不出来。
- **文件夹名是每行的一段前缀，没有 `title` 悬浮提示**。原来行首那格文件夹名带着完整路径的 tooltip，去掉那格时没有另找一个地方补，所以想知道完整路径只能看侧边栏。
- **每行都要读一次文件夹名**。这是"拆掉分块"换来的：一个文件夹一块时名字只说一次，但块会按顺序吃光额度、把别的文件夹饿死。现在靠行首那段淡灰小字说，代价是一屏上它会重复多次。
- **等你的那两块不看"有多新"**。一条半年前卡住的对话会一直顶在最上面，直到你处理它或归档它——这是有意的（压得越久越该浮上来），但也就意味着**这个列表不会自己变干净**。
- **`进行中` 那一块的顺序是"最近使用"，不是"谁先开始跑"**。跑得最久的不一定在最上面，因为那一块不回答"谁更急"。
- **文件夹只作为行的标签**，不参与排序、也不参与分块。注册表没发布时每行没有前缀，列表照旧按时间倒排。
- **弹窗的 3 小时窗口和 20 条一批是写死的常量**（`PALETTE_WINDOW_MS` / `PALETTE_LIMIT` / `PALETTE_STEP`），没有做进设置页。按理说这几项是最该暴露给用户的 tunable。
- **切换对话走 `uiWorkspace.openSession(id)`**，它同时用于侧边栏面包屑，所以从任务窗切过去和点侧边栏的观感一致。但它只切主视图，侧边栏的展开状态由宿主自己维护。
- **重命名走 `sessions.using`**，它会把那条会话短暂 retain 并打开一次（加载历史），然后立刻释放。所以给很久没打开的对话改名会有一点加载开销。
- **文件夹归属依赖宿主发布 `workspaces` 注册表**，而且依赖它给每条会话标好归属。没有注册表时每行就没有前缀——不是显示错误的名字，而是不显示。
- **推理等级只改当前这一条对话**，不改"新会话的默认"。而且只能从宿主公布的档位里选——适配器没公布等级的模型，`q` 只能提示一句。
- **推理等级只走"当前屏幕上那条对话"**（按 `mainView` 保留关系认，和 Esc 的保护判据同一个）。侧边栏里没打开的那条改不到。
- **换模型会在下一条请求前插一条宿主自己的提示**（`[model changed: …]`），而且切换可能减少提供方侧的缓存复用。插件改不了这一条，但知道它存在才不会被它吓一跳。
- **常用模型清单是全局的**，不分对话，也不跟着账号走（存在 `localStorage`）。换台设备要重勾一次。
- **模型窗的外观跟着任务窗的字体大小走**（`paletteFont`），宽度、高度、行距、弹出位置这四项它不吃——那四项是任务窗自己的，模型窗是固定的小卡，居中弹出。
- **模型窗宽度固定**（`min(680px, 92vw)`），不跟内容走。跟着内容走的话，选中行换一个档位数量不同的模型，卡片就会在指针底下变宽——看起来像页面在加载，而不是选中项在动。挤不下时裁的是档位。
- **模型窗开着时任务窗打不开**：`f` 被模型窗吞掉。两个窗不叠加（宿主里没有这种用法，叠起来键盘归谁说不清）。
- **模型窗里没有搜索框**，清单多长就列多长。清单是手勾的，通常只有几个。
- **只有选中的那一行列出全部档位**，其余行只标会落在哪一档——决定只发生在选中行上。这是「每行少一点」的取舍：要看别的模型的档位，先 `d` / `e` 移过去。
- **档位只在模型窗里能改**：`Tab`（`modelLevelKey`）和 `q` 都只在窗开着时有意义，窗关着时 `q` 是页面的推理等级键、`Tab` 是普通字符。
- **档位标记不做逐行记忆**：`Tab` 改过的档位属于你正停在的那一行，移到别的行就丢掉。一次选择、一次确定。
- **不公布档位的模型无法指定档位**：行上显示「无档位」，`Tab` 只提示一句，`w` 只切模型。
- **模型名不保证对齐**：`当前` 是名字前的徽标而非独立一列，所以没被标记的行名字从最左边起。少占宽度是低频操作下更值的取舍。
- **档位栏挤不下时裁自己**：名字很长、或某个模型档位特别多时，被裁掉的是档位而不是提供方。正常情况不触发。
- **设置页的常用模型列表只在打开那一页时读一次目录**。目录读失败会给一个「重读」按钮；换模型、换账号之后不会自己刷新。
- **切换后不聚焦输入框**（默认开）。关掉这一项，就退回宿主的行为：三个时刻光标都会被塞进输入框，Esc 是你唯一的出路。
- **不注册进 `ctx.shortcuts`**，因此不出现在「快捷键速查」里、也不参与它的冲突校验。代价是换来了裸字母键在 Desktop 原生键盘桥接下不被抢占。
- **只支持单字符键**，不支持 `Ctrl+D` 这类组合键。
- **归档走宿主的 `uiWorkspace.archiveSession`，而且刻意不带 `stopActivity`**。所以**正在跑任务的对话按 `g` 不会归档**，只会提示你先停。这是有意的：带上那个参数，一个按键就能停掉你根本没打算停的任务。插件也不提供"归档并停止"的组合键。
- **归档没有撤销键，也没有确认框**。`g` 一按就归档（宿主自己的动作），和手动归档一样不可逆；要找回来得走宿主自己的「已归档」入口。没有确认框是因为任务窗里那几行本来就是"选中 + 一个键"的节奏，加一层确认会把它打断——但这也意味着**误按 `g` 没有回头路**。
- **归档的是屏幕上那条时，主视图会跟着清空**。这是宿主 `archiveSession` 自己的行为（它会把 `mainReference` 清掉），插件没插手，也拦不住。
- **`g` 只在任务窗里有效**。它是窗的键，不是页面的键——想归档哪条，先 `f` 开窗选中它。
- **任务窗或模型窗开着的时候 `e` / `d` 归它**。想两者同时拥有，就把任务窗的上下翻键改到 `j` / `k`，`d` / `e` 会落回页面（两个窗共用这一对键，所以改一次两处都跟着变）。
- **改动 `lib/client.js` 后需要重启进程**，运行中的模块版本不会热替换。
- **任务窗只在这次打开期间常驻**：刷新页面、重载插件、重启客户端都会把它收起来，需要再按一次 `f`（和计时不同，计时会落盘）。
- **阶段是手动标的，不会自己变**。这一版没有任何自动判断——对话该进哪个阶段由你点那个词（或按 `s`）决定，插件不会替你猜。自动化的入口是那个词表（`PHASES`）和账本（`PHASES_MODEL`）：新增一个来源（goal 投影、Agent 自己写的标记）只要往账本里写同一个词，这一格和存储都不用改。
- **标注只在这台浏览器里**。阶段落在 `localStorage`，跟着设备走，不跟着账号走。
- **看板是纯画布手势**：没有选择游标，也没有"用键盘把卡片挪到另一块"这种键。它回答的是"东西在哪"，摆东西本来就是拖（会话卡片按住拖出去、拖回目标里；想法卡片拖握把）。位置只在拖动松手时写入；能靠键盘做的只有 `j`（开/关）、`i`（把当前对话放到看板）、`Esc`（取消拖动 / 关悬浮窗）和 `d` / `e` 滚动指针下那一块。
- **看板的"今天"读的是 `updatedAt`**，不是创建时间——宿主的会话列表根本不发创建时间。所以"今天动过的"不等于"今天建的"，反过来也成立：今天建的对话如果没动过（比如建完就放着），`updatedAt` 就是创建那一刻，一样会进来。
- **看板的排列只存在这台浏览器**，不跟账号走，也不进 git。两处页面同时开着看板时，各自读到的都是最新写下的那份。存储是 `dsh-vim/board/v1` 的 v2 文档：**0.28 及以前的"列"读进来时只剩 `★` 和"删掉"两个标记**，列本身丢掉，因为工作区块已经自动成列。文字卡片也在这份文档里，不在 `notes`。
- **分叉线只认这个客户端亲眼看到的分叉**。宿主给普通分叉写下的子会话里没有父会话 id，插件只能从加载那一刻起包住 `sessions.fork` 记父子；在那之前存在的分支、或在别的客户端里做的分叉，看板当作独立会话显示，不猜、不伪造一条线。侧边栏分叉和快捷键分叉走同一个 `sessions.fork`，所以它们也会被记下；但**父会话不在这块工作区时，只画"分叉自「名字」"，不画线**。
- **"交给会话"依赖宿主的输入框**。文字卡片拖到 `进入` 上时，插件先打开这条会话，再等输入框出现（最多约 1.5 秒），用编辑器的 `insertText` 命令或一次原生 `paste` 事件把字放进去。宿主换了编辑器、且既不吃 `insertText` 也不吃 `paste` 时，卡片不会丢：它留在原地并提示没找到输入框。**它只填草稿，不会自动发送**；发不发永远是你的那一下。
- **连线是按渲染后的位置量的**。会话卡片在块里的位置由块的布局和缩进决定，插件不拥有那套排版，所以在每次重画之后用 `getBoundingClientRect` 去量，画一条旋转的细线。目标会话被 `★` 过滤掉、或所在块被折起来时没有线可量，卡片头上仍然写着"已连到「名字」"，链接本身不丢。
- **看板里的卡片也显示运行状态**（0.27 起）：行首的进行中 / 等你 / 刚刚完成小标签，和 F 弹窗同一个状态源、同一套优先级。在那之前看板确实不看状态，F 弹窗才是唯一看那一栏的地方——现在两边都看，看板看的是"哪些在跑、该接着处理谁"，F 弹窗看的还是完整的排队顺序。
